# L0.1 · Your workbench: VS Code, Claude Code, Codespaces, Git

<p class="lesson-meta">Day 0 · Basic → Advanced 45 min · Leader 20 min · Prerequisites: none</p>

**Objectives** — by the end you can: open the course repository in VS Code (locally or in GitHub Codespaces); start a
conversation with Claude Code; ask it to explain the project; find where data, recipes and outputs live; and save your work with Git
— without typing code.

## 1. Business question

> "Can I get a reliable analysis environment running today, on a locked-down corporate laptop, that my whole team can reproduce?"

## 2. Concept

=== "Basic → Advanced"

    **Four pieces, each with one job:**

    | Piece | What it is | Why you need it |
    | --- | --- | --- |
    | **VS Code** | A free editor where files, a terminal and Claude Code live side by side | Your single workspace |
    | **Claude Code** (VS Code extension) | An AI assistant that reads the repository, runs analyses and edits files when you ask | You instruct it in plain English; it writes and runs the code |
    | **GitHub Codespaces** (or the dev container) | A ready-made cloud computer with Python and every library pre-installed | No installation on your laptop; everyone gets an identical setup |
    | **Git** | A history of every change to the repository | You can see what changed, undo mistakes, and share work |

    **Option A — Codespaces (recommended for corporate laptops).** On the repository page click **Code → Codespaces → Create
    codespace**. A browser VS Code opens with everything installed (the setup comes from `.devcontainer/`). Install or enable
    the Claude Code extension when prompted.

    **Option B — local.** Install VS Code, the *Dev Containers* extension and Docker, clone the repository, then choose
    **Reopen in Container**. If Docker is not allowed, ask Claude Code to "set up a local Python environment for this repo using uv
    and the pinned versions in `pyproject.toml`".

    **Tour of the repository** (ask Claude Code to show you each folder):

    | Folder | Contains |
    | --- | --- |
    | `data/` | The generated datasets (after L0.3) with data dictionaries and data cards |
    | `toolkit/` | Reusable analysis recipes and their configuration files |
    | `outputs/` | Every analysis you run, in dated folders |
    | `docs/` | This website |
    | `CLAUDE.md` | The working rules Claude Code follows in this repository |

    **Your first conversation.** Open the Claude Code panel and paste the expert prompt below. Read the answer; then open
    `CLAUDE.md` yourself and check that the summary matches.

=== "Leader"

    **Refresh in two minutes:** the course standardises the environment (dev container / Codespaces) so every analyst runs the
    same Python and library versions; Claude Code operates inside the repository under rules in `CLAUDE.md`; Git provides an audit
    trail of every change.

    **Where your judgement matters — setting team standards:**

    - **Approved environments only.** Analyses on company data run where your data-protection policy allows (e.g. Codespaces
      in your organisation's GitHub, or approved VDI). Decide this *before* the first project.
    - **`CLAUDE.md` is team policy in code.** It tells the assistant to state assumptions, never invent numbers, report row loss,
      and avoid protected attributes. Review and extend it for your team's regulators and data.
    - **Every analysis in Git, reviewed by pull request.** The audit question "who changed this threshold and why?" must have an answer.
    - **Reproducibility is a control, not a nicety.** Same seed, same config, same data hash → same numbers. Ask for the
      `run_manifest.json` before you accept a number in a deck.

## 3. Prompt cards

<div class="prompt-card" markdown>

**Weak:** "what is this"

**Better:** "Explain what this repository is for."

**Expert:** "You are helping me start a statistics bootcamp. Read `README.md`, `CLAUDE.md` and the folder structure. In under
200 words tell me: what the repository is for, where data, recipes and outputs live, the five rules you will follow when
analysing data here, and the first three commands a learner needs on Day 0. Do not run anything yet."

</div>

**What to verify in the answer:** it should mention *both* datasets, the toolkit, the `outputs/` folder, and rules such as
"state assumptions before running" and "never state a number not computed". If it invents folders that do not exist, say so —
that is your first lesson in checking AI output.

??? tip "🛠 Learn by doing — optional vibe-coding lab (15–20 min)"
    1. Open the repository in Codespaces (or VS Code) and ask Claude Code: "Explain this project in five bullet points and list the folders I will use most."
    2. Ask it to run `make quick` and tell you, step by step, what each stage checked.
    3. Change one thing: ask it to show the last three Git commits in plain English.
    4. Explain it back: how would you prove to a colleague that your results are reproducible?

## 4. Saving work with Git (no commands to memorise)

| You say | Claude Code does |
| --- | --- |
| "Show me what changed since my last commit." | Lists changed files and a summary of differences |
| "Commit my changes with a clear message describing what and why." | Stages and commits; shows you the message first |
| "Undo my last change to `toolkit/configs/x.yaml`." | Restores the previous version |

## 5. Exercises
