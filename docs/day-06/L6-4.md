**Objectives** — you can: separate training, validation and test data; use stratified, grouped and time-series cross-validation;
tune hyperparameters without leaking the test set; explain bias–variance; detect target, temporal and preprocessing leakage; and insist
on out-of-time validation for anything deployed over time.

## 2. Concept

=== "Basic → Advanced"

    ### 2.1 Leakage: the F10 trap

    Adding `collections_flag` and `recovery_amount` to the default model:

    | Model | Test AUC |
    | --- | --- |
    | application features | 0.841 (logistic) |
    | + collections_flag, recovery_amount | **0.987** |

    Permutation importance names **`recovery_amount`** as dominant. Both fields are recorded *after* default (accounts in
    collections default at 23.8%; recovery is only non-zero after charge-off). They will not exist when
    the decision is made. The recipe raises a **leakage alert** whenever test AUC exceeds 0.95 for credit data.

    | Leakage type | Example | Defence |
    | --- | --- | --- |
    | target leakage | post-outcome fields (collections, recovery) | feature timeline audit |
    | temporal leakage | features computed over windows that include the outcome (retail recency at week 104) | observation point |
    | preprocessing leakage | scaling/imputing/encoding fitted on all data before splitting | fit inside a pipeline on training folds only |
    | group leakage | same customer in train and test | grouped CV by customer |

    ### 2.2 Cross-validation done right

    5-fold stratified CV of the logistic model: AUCs 0.827, 0.838, 0.833, 0.834, 0.84 → mean 0.834 ± 0.005.
    The spread tells you how much a single split could mislead. Use **stratified** folds for rare outcomes, **grouped** folds when
    customers repeat, **time-series** folds (train on the past, validate on the next period) for anything deployed over time.

    ```mermaid
    flowchart LR
      A[All accounts by origination date] --> TR[Train: 2023–2024Q2] --> CV[K-fold CV inside train for tuning]
      A --> VA[Validation: 2024Q3–Q4]
      A --> OOT[Out-of-time test: 2025 — touched once]
      CV --> M[Chosen model] --> OOT
    ```


    ### 2.3 Tuning without fooling yourself

    Small grid for gradient boosting (3-fold CV on the training split only):

    | Setting | CV AUC |
    | --- | --- |
    | lr0.03_leaves7 | 0.82 |
    | lr0.03_leaves31 | 0.813 |
    | lr0.1_leaves7 | 0.819 |
    | lr0.1_leaves31 | 0.806 |
    

    Best: `lr0.03_leaves7`; range 0.014 AUC — tuning matters far less than features and validation design.
    The **test set is touched once**, after tuning. Random search or Bayesian optimisation scale better than grids for many parameters.

    ### 2.4 Out-of-time validation

    Train on vintages ≤ 2024Q4 (17,457 accounts, default 2.56%), test on 2025Q1–Q3
    (7,543):

    | Model | Random-split AUC | Out-of-time AUC | Predicted default | Actual default |
    | --- | --- | --- | --- | --- |
    | logistic | 0.841 | **0.806** | 4.22% | **7.33%** |
    | gradient boosting | 0.827 | 0.785 | 3.36% | 7.33% |

    Ranking degrades a little; **calibration breaks**: the model predicts ~4.22% when 7.33%
    default — the new partner population (L5.7) is riskier than anything in training. A random split would never show this.

    ### 2.5 Bias–variance

    Simple models: high bias, low variance (stable, may miss structure). Flexible models: low bias, high variance (fit noise). The deep
    tree (train AUC 1.0, test 0.564) is the variance extreme.

=== "Leader"

    !!! abstract "Refresh"
        Validation design decides whether a score means anything. Leakage makes models look brilliant and fail in production;
        out-of-time tests reveal drift that random splits hide.

    **Judgement points**

    - **AUC above domain norms is a red flag** (credit application models: ~0.70–0.85). Ask which feature dominates.
    - **Require out-of-time validation and a calibration check** before approving any risk model; a model under-predicting default by
      40% would under-provision and under-price.
    - **Pipelines are a control:** all preprocessing inside the cross-validated pipeline, never on the full data.

    !!! tip "Coaching card"
        Ask: *"Explain why this score is suspicious"* — and make the junior show the dominant feature's timeline.

## 5. Output anatomy — validation signals in `rcp_classifier`

| Signal | Meaning |
| --- | --- |
| Leakage alert | test AUC above `leakage_auc`; dominant feature named |
| train vs test AUC gap > 0.05 | overfitting warning |
| mean predicted vs actual | calibration in level — flagged if > 25% off |
| split line | random or out-of-time with the cutoff |

??? example "R6-8 · Applied · Time-series cross-validation design"

    **Deliverable:** Describe a rolling-origin validation for a weekly model (folds, horizons).

    ??? success "Expected finding and model answer"

    **Leader drill:** How many folds are enough?
