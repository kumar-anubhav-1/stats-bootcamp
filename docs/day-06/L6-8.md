## 2. Concept

=== "Basic → Advanced"

    ### 2.1 The ladder

    <div class="sb-chart" data-chart="ml_ladder" data-caption="Each dot is one algorithm. Moving right = more complex and data-hungry; moving down = harder to explain. Hover for a retail or banking use."></div>

    | Algorithm | How it works (one sentence) | Formula / key idea |
    | --- | --- | --- |
    | Linear regression | fits the straight line (plane) that minimises squared errors | ŷ = wᵀx + b |
    | Logistic regression | linear score squeezed into a probability by the sigmoid | P(y=1) = 1 / (1 + e^−(wᵀx+b)) |
    | Naive Bayes | multiplies per-feature likelihoods, assuming features are independent | P(class \| x) ∝ P(class) Πᵢ P(xᵢ \| class) |
    | K-nearest neighbours | predicts from the k most similar past cases | majority vote / average of k neighbours |
    | Decision tree | asks yes/no questions on features ("utilisation > 80%?") | splits that most reduce impurity |
    | Random forest | averages hundreds of trees grown on random samples and features | ŷ = average of hₜ(x) |
    | Gradient boosting | adds small trees one after another, each fixing the previous errors | Fₘ(x) = Fₘ₋₁(x) + η·hₘ(x) |
    | Support vector machine | finds the boundary with the widest margin; kernels let it bend | maximise margin, ε-insensitive for regression |
    | K-means | puts each point with its nearest of k centres, then moves the centres | min Σ ‖x − μₖ‖² |
    | PCA | rotates the data to new axes ordered by how much variance they carry | eigenvectors of the covariance matrix |
    | Neural network | layers of weighted sums passed through non-linear switches | a = σ(Wx + b), stacked |
    | Transformer | a network where every token "attends" to every other token | softmax(QKᵀ/√d)V |
    | Diffusion model | learns to remove noise step by step, so it can generate from pure noise | reverse a gradual noising process |

    ### 2.2 Finance bake-off: probability of default

    Same 9 features, same stratified 70/30 split, base default rate 4.0%. (KNN and SVM were trained on 6,000
    accounts because they slow down sharply with more rows — a real-world cost too.)

    | Model | Test AUC | PR-AUC | Training rows | Explainability |
    | --- | --- | --- | --- | --- |
    | Logistic regression | **0.826** | 0.143 | 17,500 | high |
    | Naive Bayes | **0.806** | 0.124 | 17,500 | medium |
    | K-nearest neighbours (k=50) | **0.755** | 0.108 | 6,000 | medium |
    | Decision tree (depth 5) | **0.795** | 0.123 | 17,500 | high |
    | Support vector machine (RBF) | **0.623** | 0.082 | 6,000 | low |
    | Random forest | **0.813** | 0.141 | 17,500 | low |
    | Gradient boosting | **0.817** | 0.145 | 17,500 | low |
    | Neural network (MLP 32-16) | **0.807** | 0.134 | 17,500 | very low |
    

    Winner: **Logistic regression**. On this structured, mostly monotone credit data the simplest model is as good as or better
    than every complex one — and it is the only one a regulator will readily accept with adverse-action reasons. SVM and KNN struggle
    with a rare target and many rows.

    ### 2.3 Retail bake-off: weekly Beverages units per store

    Features: store size, format, region, city tier, holiday and payday weeks, month, seasonality, promotion share, last year's same
    week and the last four weeks' average. Train on all weeks except the last 16; test on those 640 store-weeks
    (average 158.0 units).

    | Model | MAE (units) | vs seasonal naive |
    | --- | --- | --- |
    | Seasonal naive (same week last year) | 27.0 | 0.0% |
    | Linear regression | 20.4 | -24.4% |
    | K-nearest neighbours (k=10) | 23.0 | -14.8% |
    | Decision tree (depth 6) | 25.0 | -7.4% |
    | Support vector regression | 19.5 | -27.8% |
    | Random forest | 20.1 | -25.6% |
    | Gradient boosting | 21.0 | -22.2% |
    | Neural network (MLP) | 22.3 | -17.4% |
    

    Every model beats "same week last year", so the features carry real signal. The best (Support vector regression) improves on
    plain linear regression by only 4.4% — worth it only if that accuracy moves stock and waste costs
    enough to pay for the extra complexity and monitoring (L7.6).

    ### 2.4 See the decision surfaces

    <div class="sb-chart" data-chart="model_zoo" data-caption="Drag the slider: ten algorithms learn default risk from just two features. Smooth = logistic/NB; patchy = KNN k=5 and the deep tree (overfit); flexible = boosting, forest, MLP. Compare train vs test AUC in the title."></div>

    ### 2.5 Unsupervised and generative rungs

    - **K-means and PCA** don't predict a target: they find structure. You used them on NorthStar customers in L8.1 (segments,
      silhouette, components).
    - **Transformers and diffusion models** are the generative top of the ladder — text and images. They are introduced, with
      interactive demos, in [L9.8](../day-09/L9-8.md).

    ### 2.6 The rules for climbing

    1. Always start with a simple, explainable baseline (linear/logistic) and a naive benchmark.
    2. Compare on the **same split**, with the **business metric** (PR-AUC for rare events, MAE/MASE for demand).
    3. Climb only if the gain is material **in money**, survives an out-of-time test (L6.4) and can be explained and monitored.

=== "Leader"

    !!! abstract "Refresh"
        Thirteen algorithms, one rule: complexity must earn its place on held-out data, in money, with explanations you can defend.

    **Judgement points**

    - **"More advanced" is not a business case.** Here the logistic model ties or beats seven complex alternatives on default risk.
    - **Ask for the bake-off table** — same split, same metric, a naive baseline row, and training/serving cost.
    - **Explainability is a requirement, not a nice-to-have**, for credit, pricing and anything customer-facing (L6.7, L9.5).
    - **Generative AI (transformers, diffusion)** is the right tool for text and images, not for tabular risk scores.

    !!! tip "Coaching card"
        Ask: *"Show me the simplest model on the same test set. What does the gain mean in pounds, and who will explain it to a customer?"*

## 5. Output anatomy — the bake-off table

| Column | Read it as |
| --- | --- |
| AUC / MAE | ranking quality / average miss on unseen data |
| PR-AUC | alert quality when positives are rare (compare with the base rate) |
| vs naive | is the model worth having at all? |
| training rows, effort | cost and scalability |
| explainability | can you give reasons for one decision? |

## 6. Scenario matrix

=== "Basic → Advanced"

    | Situation | First choice | Then try |
    | --- | --- | --- |
    | numeric target, few clear drivers | linear regression | GBM if non-linear |
    | regulated yes/no decision | logistic / scorecard | GBM + explanations, with sign-off |
    | text to route quickly | Naive Bayes | pretrained transformer embeddings |
    | "customers like this one" | KNN | embeddings + nearest neighbours |
    | many interacting signals (fraud) | random forest / GBM | — |
    | groups without labels | k-means | GMM, DBSCAN |
    | too many correlated features | PCA | — |
    | images, long text, generation | neural networks, transformers, diffusion | — |

=== "Leader"

    | Proposal | Ask for | Norm |
    | --- | --- | --- |
    | replace logistic with GBM | same-split comparison, out-of-time, PR-AUC, explanations | gain ≥ business threshold |
    | neural network for tabular risk | why not GBM? | rarely justified |
    | vendor "AI forecast" | backtest vs seasonal naive and our model | MASE < 1 and better than ours |
    | GenAI for complaints | evaluation set, privacy, human review | governed use case |
