## 2. Concept

=== "Basic → Advanced"

    ### 2.1 Trees and ensembles in one table

    | Model | Idea | Strength | Weakness |
    | --- | --- | --- | --- |
    | Decision tree | split data on the most informative question, repeatedly | readable rules, interactions | unstable, overfits when deep |
    | Random forest | average many deep trees on bootstrap samples and random feature subsets | robust, little tuning | less interpretable, big |
    | Gradient boosting | add small trees that correct the current errors | best tabular accuracy when signal is complex | needs tuning; overfits quietly |

    <div class="sb-chart" data-chart="tree_depth" data-caption="Training AUC climbs to 1.0 as the tree memorises accounts; test AUC peaks early."></div>

    ### 2.2 Default model bake-off (17,500 train / 7,500 test, 18 application features)

    | Model | Test AUC | PR-AUC | KS | Brier |
    | --- | --- | --- | --- | --- |
    | logistic | 0.841 | 0.171 | 0.547 | 0.0359 |
    | tree_depth4 | 0.806 | 0.142 | 0.492 | 0.0361 |
    | tree_deep | 0.564 | 0.057 | 0.139 | 0.0741 |
    | random_forest | 0.826 | 0.174 | 0.522 | 0.0354 |
    | gbm | 0.827 | 0.17 | 0.52 | 0.0357 |
    | logistic + engineered terms (util > 80/90%, young × high DTI) | 0.843 | 0.169 | 0.561 | 0.0361 |

    - The **deep tree** memorises the training data (train AUC 1.0) and collapses on test.
    - **Gradient boosting** reaches train AUC 0.897 but test AUC 0.827 — no better than
      logistic (-0.014). The signal here is mostly additive and monotone (bureau score, channel, utilisation), which a
      logistic model with a couple of engineered terms captures.
    - Out of time (L6.4) the gap widens in logistic's favour.

    **Lesson:** gradient boosting is the strongest *general* tabular learner, but on well-understood credit data with sensible
    features it often adds little. Always keep a logistic baseline.

    ### 2.3 When boosting does win

    Many weakly informative features, strong interactions nobody has engineered, non-monotone effects, very large data — e.g. fraud
    with device/behaviour signals, demand forecasting features, marketing response. Even then, check out-of-time performance and
    stability.

=== "Leader"

    !!! abstract "Refresh"
        Trees capture interactions; ensembles stabilise them. Boosting is powerful but not magic — on this credit data the logistic
        baseline matches it and is more stable and explainable.

    **Judgement points**

    - **Demand the baseline.** A GBM proposal without a logistic comparison on the same out-of-time test is incomplete.
    - **Complexity has running costs:** monitoring, explainability (adverse-action reasons), retraining, validation effort.
    - **A small AUC gain may still pay** in large portfolios — translate it into money (L6.6) before deciding.

    !!! tip "Coaching card"
        Ask: *"Train vs test vs out-of-time AUC for both models, and what decisions change if we switch?"*

## 5. Output anatomy — model comparison in `rcp_classifier`

| Column | Read as |
| --- | --- |
| ROC-AUC / Gini | ranking quality (Gini = 2·AUC − 1) |
| PR-AUC | ranking quality where it matters for rare events |
| KS | max separation of goods and bads (credit convention) |
| Brier | probability accuracy (lower is better) |
| train AUC | gap vs test > 0.05 → overfitting warning |

## 8. Exercises

### Retail · NorthStar

??? example "R6-4 · Basic · Trees on retail data"
    **Business framing:** Would gradient boosting rescue the repeat-purchase model?

    **Deliverable:** GBM vs logistic test AUC on the honest features.

    ??? success "Expected finding and model answer"
        **Expected:** GBM 0.489 vs logistic 0.501. *(tolerance: ± 0.03)*

        **Model answer:** No algorithm finds signal that isn't there.

        **Common wrong answer:** Switching algorithms hoping for lift.

    **Leader drill:** When is 'try a fancier model' the wrong instinct?

??? example "R6-5 · Applied · Overfitting a deep tree"
    **Business framing:** Explain tree overfitting with the default data (shared case study).

    **Deliverable:** Train vs test AUC of an unrestricted tree; depth-4 tree; random forest.

    ??? success "Expected finding and model answer"
        **Expected:** Deep tree train 1.0 / test 0.564; depth-4 test 0.806; forest 0.826. *(tolerance: ± 0.02)*

        **Model answer:** A deep tree memorises noise; constraining depth or averaging many trees fixes it.

        **Common wrong answer:** Using training AUC.

    **Leader drill:** How would you explain overfitting to a store manager?

### Finance · Meridian

??? example "F6-2 · Basic · Logistic vs boosting"
    **Business framing:** Should we replace the logistic default model?

    **Deliverable:** Run `finance_classifier_default.yaml`: test AUC, PR-AUC, KS, Brier, train AUC for both.

    ??? success "Expected finding and model answer"
        **Expected:** Logistic ≈ 0.841, GBM ≈ 0.827 (train 0.897). *(tolerance: ± 0.01)*

        **Model answer:** No meaningful gain; GBM overfits more. Keep logistic, use GBM as a challenger.

        **Common wrong answer:** Switching because GBM is 'more advanced'.

    **Leader drill:** What evidence would justify switching?

??? example "F6-3 · Applied · Engineered logistic"
    **Business framing:** Capture non-linearity without a black box.

    **Deliverable:** Add utilisation > 80% / > 90% flags and a young × high-DTI flag; compare AUC.

    ??? success "Expected finding and model answer"
        **Expected:** AUC 0.843 vs 0.841 plain. *(tolerance: ± 0.005)*

        **Model answer:** Small, explainable terms recover what a GBM would learn.

        **Common wrong answer:** Adding dozens of interactions blindly.

    **Leader drill:** Where is the line between engineering and overfitting?
