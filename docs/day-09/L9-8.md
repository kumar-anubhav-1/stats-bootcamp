## 2. Concept

=== "Basic → Advanced"

    ### 2.1 One neuron = a logistic regression

    A neuron weighs its inputs, adds a bias and squashes the result: **z = w₁x₁ + w₂x₂ + b, a = σ(z)**. Fitted on Meridian cards
    with two inputs: w(utilisation) = 1.81, w(bureau score) = -0.021, b = 9.789.

    For a customer at 90% utilisation with bureau score 620: z = 9.789 + 1.81 × 0.9
    + (-0.021) × 620 = **-1.586**, so σ(z) = **17.0%** probability of default.
    A neural network is thousands of these, stacked in layers.

    ### 2.2 Activation functions — the non-linear switches

    <div class="sb-chart" data-chart="activations" data-caption="Without these, stacked layers would collapse into one linear model. ReLU is the default in hidden layers; sigmoid turns a score into a probability."></div>

    ### 2.3 Forward pass, loss, backpropagation

    ```mermaid
    flowchart LR
      X[Inputs: utilisation, DTI, bureau…] --> H1[Layer 1: z = W₁x + b₁, a = ReLU z] --> H2[Layer 2] --> O[Output: σ → PD]
      O --> LS[Loss: cross-entropy vs actual default]
      LS -.->|backpropagation: chain rule sends the error backwards| H2
      H2 -.-> H1
      LS --> UP[Optimiser updates every weight: θ ← θ − η∇L]
    ```

    | Piece | Formula | In plain words |
    | --- | --- | --- |
    | Forward pass | z⁽ˡ⁾ = W⁽ˡ⁾a⁽ˡ⁻¹⁾ + b⁽ˡ⁾, a⁽ˡ⁾ = σ(z⁽ˡ⁾) | matrix multiplication, layer by layer (L2.7) |
    | Regression loss | MSE = (1/n) Σ (yᵢ − ŷᵢ)² | average squared forecast miss |
    | Classification loss | cross-entropy = −(1/n) Σ [y log ŷ + (1−y) log(1−ŷ)] | heavy penalty for confident wrong answers |
    | Backpropagation | δ⁽ˡ⁻¹⁾ = (W⁽ˡ⁾)ᵀ δ⁽ˡ⁾ ⊙ σ′(z⁽ˡ⁻¹⁾); ∂L/∂W⁽ˡ⁾ = δ⁽ˡ⁾(a⁽ˡ⁻¹⁾)ᵀ | how much each weight contributed to the error |
    | Gradient descent | θ ← θ − η ∇L(θ) | step downhill; η is the learning rate |
    | Adam | moving averages of gradients (m) and squared gradients (v), bias-corrected | adaptive step size per weight |

    ### 2.4 Gradient descent on a real loss surface

    <div class="sb-chart" data-chart="gradient_descent" data-caption="The bowl is the actual squared-error loss of a two-parameter Snacks price-response model. Pick an optimiser: too small a learning rate crawls, too large oscillates or diverges, Adam adapts. Drag to rotate."></div>

    ### 2.5 Overfitting and regularisation

    A 2,625-parameter network trained on 3,000 accounts:

    | | Training loss at epoch 120 | Best validation loss (epoch) | Validation loss at epoch 120 |
    | --- | --- | --- | --- |
    | weak penalty | 0.0717 | 0.1449 (epoch 15) | **0.2177** |
    | strong L2 penalty | 0.1354 | 0.1395 (epoch 29) | **0.1399** |

    <div class="sb-chart" data-chart="training_curve" data-caption="Dotted = training loss, solid = validation loss. The unpenalised network keeps improving on training data while getting worse on new accounts after about epoch 15."></div>

    Fixes: **L2** (+λΣw², same as ridge), **L1** (+λΣ|w|, same as lasso), **dropout** (randomly switch off neurons while training
    so none becomes indispensable), **early stopping** (stop when validation loss stops improving). Key hyperparameters: learning
    rate, batch size, layers and units, activation, optimiser, penalty, epochs, early-stopping patience.

    ### 2.6 Architectures for different data

    | Architecture | Built for | Retail use | Finance use |
    | --- | --- | --- | --- |
    | Feed-forward (MLP) | tabular, embeddings | product embeddings for recommendations | large-scale transaction scoring |
    | CNN (convolutions, pooling, feature maps) | images | on-shelf availability from shelf photos | cheque and ID document reading |
    | RNN / LSTM / GRU | sequences | basket sequences | transaction streams for fraud |
    | Transformer (self-attention, positional encoding) | text, long sequences, multimodal | review summaries, product copy | complaint triage, policy Q&A |

    ### 2.7 Self-attention

    <div class="sb-chart" data-chart="attention" data-caption="Illustrative weights for one complaint sentence: 'hardship' attends strongly to 'losing' and 'job', 'plan' to 'offer'. In a real transformer, Q, K and V are learned projections and many heads run in parallel."></div>

    Each token builds a **query**, **key** and **value**; attention weights = softmax(QKᵀ/√d); the output mixes the values. This is
    how "missed payments" is read in the context of "after losing job" — the signal a hardship-detection model needs.

    ### 2.8 LLMs: pre-training, post-training and RAG

    ```mermaid
    flowchart LR
      PRE[Pre-training: predict the next token on huge text] --> SFT[Supervised fine-tuning on example answers]
      SFT --> RM[Reward model from human preferences] --> RLHF[RLHF: optimise toward preferred answers] --> APP[Assistant]
      KB[Policies, product data] --> CH[Chunks] --> EMB[Embeddings in a vector DB]
      Q[Customer question] --> RET[Retrieve relevant chunks] --> APP
      EMB --> RET
    ```

    **RAG** (retrieval-augmented generation) makes the model answer from *your* documents with citations — essential for policy or
    product questions, where a hallucinated answer is a compliance breach.

    ### 2.9 Diffusion models: generating by denoising

    <div class="sb-chart" data-chart="diffusion" data-caption="Step through: real data (three customer segments) is gradually noised until it is pure noise; then the reverse process removes noise step by step and new samples appear in the same three groups. Image generators do this with millions of pixels."></div>

    Training teaches a network to predict the noise that was added at each step; generation starts from random noise and repeatedly
    subtracts the predicted noise. Uses: product and lifestyle imagery, synthetic rare-fraud examples for testing detectors — always
    labelled as synthetic and checked for bias and leakage of real customer data.

=== "Leader"

    !!! abstract "Refresh"
        A network is stacked logistic regressions trained by gradient descent. Transformers read context through attention;
        diffusion models generate by reversing noise. Power comes with opacity, data hunger and new failure modes.

    **Judgement points**

    - **Training curves tell you if a model memorised:** ask to see validation loss by epoch and what stopped training.
    - **For tabular risk, the neuron view matters:** a one-neuron "network" is logistic regression — insist on the comparison (L6.8).
    - **Transformers need grounding:** RAG with citations, evaluation sets and human review for regulated outputs.
    - **Generated images and data must be labelled** and governed (copyright, bias, misuse, customer privacy).

    !!! tip "Coaching card"
        Ask: *"What was it trained on, how was it validated, where are the citations, and who reviews its mistakes?"*

## 5. Output anatomy

| Item | Read it as |
| --- | --- |
| training vs validation loss | gap and upturn = overfitting |
| best epoch | where early stopping would stop |
| parameter count | capacity; compare with number of training rows |
| attention map | which inputs influenced an output (not a full explanation) |
| diffusion step | noise level; generation runs from high to low noise |

## 6. Scenario matrix

=== "Basic → Advanced"

    | Symptom | Likely cause | Fix |
    | --- | --- | --- |
    | loss explodes | learning rate too high | lower η, use Adam |
    | loss barely moves | η too low, unscaled inputs | scale inputs, raise η |
    | training ≪ validation loss | overfitting | L2/dropout/early stopping, more data |
    | both losses high | underfitting | bigger network or better features |
    | LLM invents a policy | no grounding | RAG with citations |

=== "Leader"

    | Proposal | Ask | Norm |
    | --- | --- | --- |
    | neural risk model | bake-off vs logistic/GBM, explanations | adopt only for material gain |
    | complaint-reading transformer | evaluation set, fairness, review loop | human-in-the-loop for decisions |
    | generated product imagery | labelling, rights, brand review | disclose AI-generated content |
