## 2. Concept

=== "Basic → Advanced"

    ### 2.1 Overfitting

    A model with many parameters relative to the data learns noise. Training fit improves; new-data performance falls.

    **Retail.** Beverages log-units model with 59 features (store dummies, promo, stock-outs, temperature, holiday and
    16 pure-noise columns). Train on weeks ≤ 78, test on weeks 79–104:

    | Training data | Model | Train R² | Test R² |
    | --- | --- | --- | --- |
    | 78 weeks (3,120 rows) | OLS | 0.876 | 0.912 |
    | | Ridge / Lasso (CV) | — | 0.912 / 0.912 |
    | **2 weeks (80 rows)** | OLS | **0.989** | **0.595** |
    | | Lasso (CV) | — | **0.813** (37 features kept, 8 of 16 noise) |

    With plenty of data (rows ≫ features) OLS is fine and regularisation changes nothing. With 80 rows and
    59 features OLS memorises the training weeks (R² 0.989) and fails on new weeks; the lasso's penalty
    holds up far better. Note that the lasso still kept some noise columns — it is a regulariser, not an oracle.

    <div class="sb-chart" data-chart="overfit" data-caption="Drag the degree: training error keeps falling, held-out error falls then explodes — overfitting you can see."></div>

    ### 2.2 The penalties

    | Method | Penalty | Effect | Use when |
    | --- | --- | --- | --- |
    | Ridge (L2) | λ Σβ² | shrinks all coefficients; keeps correlated ones together | many correlated predictors (income + limit) |
    | Lasso (L1) | λ Σ\|β\| | shrinks and sets some to exactly 0 | feature selection, sparse models |
    | Elastic net | mix | selection + stability with correlated groups | many correlated candidates |

    Standardise predictors first (the recipes and scikit-learn pipelines do). λ is chosen by **cross-validation** — shuffle the folds
    unless the data are time-ordered (then use time-based folds, L6.4).

    ### 2.3 Finance: 40 candidates (20 real, 20 noise), 4,000 training accounts

    | Model | Features | Noise kept | Test AUC |
    | --- | --- | --- | --- |
    | Unpenalised logistic | 40 | all | 0.816 (train 0.859) |
    | Lasso, best CV AUC | 7 | 0 | 0.82 |
    | Lasso, 1-SE rule | 3 | 0 | 0.811 |

    The unpenalised model loses AUC from train to test (overfitting); the lasso with the best CV penalty keeps a handful of real
    variables, drops the noise and predicts at least as well. The **1-SE rule** (the simplest model within one standard error of the
    best) gives an even smaller model at almost no cost: top drivers partner, bureau_score, income_missing, age, utilisation.

    ### 2.4 Information criteria

    | Beverages model (full data, store FE) | k | AIC | BIC |
    | --- | --- | --- | --- |
    | temp+holiday | 42 | -1,107 | -841 |
    | +promo+stockout | 44 | -1,314 | -1,035 |
    | +region×temp | 47 | -1,365 | -1,067 |
    

    Lower is better. BIC penalises extra parameters more (log n per parameter); both prefer adding promotions and stock-outs. The
    region × temperature interaction also lowers AIC and BIC — but the planted temperature effect is the same everywhere, so check the
    size of the gain and whether it holds out of sample before believing it.

=== "Leader"

    !!! abstract "Refresh"
        Overfitting = learning noise. Regularisation trades a little bias for much less variance; cross-validation chooses how much.
        With lots of data relative to features it barely matters; with many features or few rows it matters a lot.

    **Judgement points**

    - **Training fit is not evidence.** Ask for held-out (and out-of-time) performance every time.
    - **Parsimony has business value:** fewer variables = cheaper data, easier monitoring, clearer adverse-action reasons. Prefer the
      1-SE model when the loss is negligible.
    - **Lasso selection is not causal.** Correlated drivers are dropped almost at random; don't read "not selected" as "doesn't
      matter".

    !!! tip "Coaching card"
        Ask: *"Train vs test performance? How was λ chosen — folds shuffled or by time? What would a 1-SE model drop?"*

## 6. Scenario matrix

=== "Basic → Advanced"

    | Situation | Approach |
    | --- | --- |
    | rows ≫ features | OLS/logistic fine; regularisation optional |
    | many features, few rows | lasso / elastic net |
    | correlated groups | ridge or elastic net |
    | compare a few nested models | AIC/BIC or likelihood-ratio test |
    | predictive use | held-out / cross-validated error decides |

=== "Leader"

    | Claim | Question | Norm |
    | --- | --- | --- |
    | "R² 0.99 on training" | test R²? | out-of-sample validation |
    | "lasso dropped income, so income doesn't matter" | correlated with limit? | selection ≠ causality |
    | "AIC improved by 3" | out-of-sample gain? | small ΔAIC on large n means little |

## 7. Planted traps and reuse drill

!!! warning "Traps"
    Unshuffled CV folds on store-sorted data drop whole stores (an easy way to get a nonsensical λ); F06 collinearity makes lasso
    pick income *or* limit arbitrarily.

**Reuse drill:** repeat the finance screen with elastic net (l1_ratio 0.5) — does it keep income and limit together?

## 8. Exercises

### Retail · NorthStar

??? example "R5-6 · Basic · Overfitting with few rows"
    **Business framing:** A junior fits a 59-feature model on two weeks of data.

    **Deliverable:** Train and test R² for OLS on weeks 77–78 vs LassoCV; features and noise columns kept.

    ??? success "Expected finding and model answer"
        **Expected:** OLS train 0.989, test 0.595; lasso test 0.813 (37 kept, 8 noise). *(tolerance: ± 0.05)*

        **Model answer:** With 80 rows and 59 features OLS memorises noise. The penalty generalises better, though it still keeps some noise.

        **Common wrong answer:** Trusting the training R².

    **Leader drill:** What minimum rows-per-feature rule would you set?

??? example "R5-7 · Applied · When regularisation doesn't matter"
    **Business framing:** Same model trained on 78 weeks.

    **Deliverable:** Test R² for OLS, ridge and lasso.

    ??? success "Expected finding and model answer"
        **Expected:** OLS 0.912, ridge 0.912, lasso 0.912. *(tolerance: ± 0.01)*

        **Model answer:** With thousands of rows per feature the penalty chosen by CV is tiny; all three agree.

        **Common wrong answer:** Expecting lasso to always win.

    **Leader drill:** How would you explain to a stakeholder why the 'advanced' method didn't help?

??? example "R5-8 · Stretch · AIC/BIC for nested models"
    **Business framing:** Should the model include promotions and a region × temperature interaction?

    **Deliverable:** AIC and BIC for the three nested models.

    ??? success "Expected finding and model answer"
        **Expected:** temp+holiday: AIC -1,107, BIC -841; +promo+stockout: AIC -1,314, BIC -1,035; +region×temp: AIC -1,365, BIC -1,067;  *(tolerance: ± 5)*

        **Model answer:** Both criteria favour promotions/stock-outs. The interaction also improves AIC/BIC — check whether it holds out of sample, since the planted temperature effect is the same in all regions.

        **Common wrong answer:** Adding the interaction because AIC fell.

    **Leader drill:** What would convince you a regional temperature effect is real?

### Finance · Meridian

??? example "F5-7 · Basic · Lasso feature screen"
    **Business framing:** 40 candidate features (20 noise) for a default model, 4,000 training accounts.

    **Deliverable:** Unpenalised vs lasso (best CV and 1-SE): features kept, noise kept, test AUC.

    ??? success "Expected finding and model answer"
        **Expected:** Full: train 0.859, test 0.816; best CV: 7 kept, 0 noise, AUC 0.82; 1-SE: 3 kept, AUC 0.811. *(tolerance: ± 0.01 AUC)*

        **Model answer:** Lasso drops noise and predicts as well with far fewer variables; 1-SE gives an even simpler model at little cost.

        **Common wrong answer:** Keeping all 40 because AUC on training is higher.

    **Leader drill:** Which model would you take to production?

??? example "F5-8 · Applied · Ridge vs lasso with collinear predictors"
    **Business framing:** Income and limit are both candidates.

    **Deliverable:** Compare ridge and lasso coefficients for income and limit (standardised).

    ??? success "Expected finding and model answer"
        **Expected:** Ridge shares the effect between them; lasso tends to keep one and zero the other. *(tolerance: —)*

        **Model answer:** Neither split is causal; choose by business meaning and stability.

        **Common wrong answer:** Concluding lasso 'proved' limit doesn't matter.

    **Leader drill:** What governance note would you add to a model using lasso selection?
