**Objectives** — you can: tell errors, genuine extremes and signals apart; flag outliers with Tukey fences, z-scores and robust
(MAD) z-scores and explain why they disagree; choose and report a treatment; apply log/Box-Cox transforms, scaling, binning and
encoding — and avoid target-encoding leakage.

## 2. Concept

=== "Basic → Advanced"

    ### 2.1 Three kinds of "outlier"

    | Kind | Example | Treatment |
    | --- | --- | --- |
    | **Error** | unit price 100× list (R02) | correct or quarantine |
    | **Genuine extreme** | bulk buyer's basket (R07) | keep; often model as its own segment |
    | **Signal** | returns-abuse cluster (R17), fraud | investigate — this is what you are looking for |

    ### 2.2 Detection rules

    | Rule | Definition | Clean baskets flagged (of 3,163) |
    | --- | --- | --- |
    | Tukey fence, k = 1.5 | above Q3 + 1.5 × IQR = 120.55 | 146 |
    | Tukey fence, k = 3 | above Q3 + 3 × IQR = 179.69 | 41 |
    | Plain z-score > 3 | (x − mean) ÷ SD | 31 |
    | Robust z-score > 3.5 | 0.6745 × (x − median) ÷ MAD | 90 |

    **Why they disagree.** On skewed data, k = 1.5 flags many ordinary large baskets. The plain z-score uses the mean and SD — both
    inflated by the very values you are hunting — so it under-flags (**masking**). On the *raw* data, the 25 decimal-shift lines sit in
    25 baskets; plain z > 3 catches only **19**, the robust score catches
    **25**. The errors raise the SD from 67.58 to 98.53.

    ### 2.3 Treatments — and what they do to the answer

    | Treatment | Mean basket |
    | --- | --- |
    | keep all | 50.52 |
    | cap at P99 | 47.23 |
    | exclude robust outliers | 43.22 |
    | 10% trimmed mean | 41.79 |
    | median (no treatment needed) | 38.94 |

    About **37.0%** of robust-flagged baskets come from 25 bulk-buying customers: one identifiable segment.

    ### 2.4 Transformations

    | Transform | What it does | Example |
    | --- | --- | --- |
    | **Log** | compresses the right tail; multiplicative → additive | income skew 12.21 → 0.45 |
    | **Box-Cox** (positive) / **Yeo-Johnson** (any sign) | finds the power that best normalises | λ = -0.101 ≈ 0 → it is essentially a log |
    | **Standardise** (z) / **min-max** | puts variables on comparable scales | needed for K-means, KNN, regularisation |
    | **Binning** | numeric → categories | scorecard bins (Day 8); loses detail |

    ### 2.5 Encoding categorical variables

    | Encoding | Use | Risk |
    | --- | --- | --- |
    | One-hot | few categories | many columns |
    | Ordinal | ordered categories (age band) | implies equal spacing |
    | **Target encoding** | many categories (branch, postcode) | **leakage** if computed on the same rows it is used for |

    A random 2,000-level code with no information about default reaches an AUC of **0.856** when target-encoded on all
    rows — and **0.512** (chance) when encoded out-of-fold. Fit encoders inside cross-validation.

=== "Leader"

    !!! abstract "Refresh"
        Error / genuine extreme / signal. Robust z (median, MAD) for skewed data; plain z masks. Treatment is a decision that moves the
        result — report it. Log for skewed positive amounts. Target encoding leaks unless done out-of-fold.

    **Judgement points**

    - **Standardise the treatment, not the threshold.** Agree team-wide: errors quarantined; genuine extremes kept and reported;
      segments like bulk buyers modelled separately. Then the number stops changing with the analyst.
    - **Never delete signals.** Fraud and abuse look like outliers. An analyst who "cleans" them away removes the business problem.
    - **Interpretability matters.** λ ≈ 0 → use log (coefficients become % effects); an exotic λ buys little and costs explanation.
    - **Leakage hides in feature engineering.** Ask how every encoded or aggregated feature was fitted.

    !!! tip "Coaching card"
        Ask: *"Show me the result with and without the treatment."* If the conclusion flips, the treatment is the finding — and it
        must be in the headline, not the appendix.

## 3. Assumptions and fallbacks

| Situation | Use | Fallback |
| --- | --- | --- |
| Skewed, one variable | robust z / percentiles | log scale then z |
| Many variables | Isolation Forest / LOF (Day 8) | Mahalanobis on robust covariance |
| Unsure error vs genuine | keep + flag + sensitivity | ask the data owner |
| Model needs symmetric inputs | log / Box-Cox | rank / quantile transform |

## 5. Output anatomy — `rcp_outliers`

| Line | Meaning | Read as |
| --- | --- | --- |
| IQR, Q1, Q3 | robust spread | fences are built from these |
| MAD | robust SD substitute (× 1.4826 ≈ SD for normal data) | basis of the robust z |
| counts per rule | sensitivity of each rule | big differences = skewed data |
| treatment table | how each choice moves mean and SD | the size of the "analyst effect" |

## 6. Scenario matrix

=== "Basic → Advanced"

    | Pattern | Meaning | Next |
    | --- | --- | --- |
    | z-score flags few, robust z flags many | masking by inflated SD | trust the robust rule |
    | Flagged units share an attribute | a segment, not noise | analyse the segment |
    | Removing outliers flips a conclusion | fragile result | report both |

=== "Leader"

    | Pattern | Likely causes | Action — why / when / when not | Norm |
    | --- | --- | --- | --- |
    | Extremes concentrated in a few customers | bulk/business buyers | **Separate segment** in pricing and CRM; not deletion | Document segment rules |
    | Extremes concentrated in a store / time | errors or abuse | **Investigate** (audit, fraud team) | — |
    | Feature suspiciously predictive after encoding | target leakage | **Reject** until fitted out-of-fold | All encoders inside CV |

## 7. Alternatives

!!! tip "What else could I try?"
    - **[Isolation Forest (global) / LOF (local) / residual-based scores](../../navigator/#N-ANOM-MULTI)** — Multivariate outliers without labels (returns abuse, unusual accounts).
    - **[Median, IQR, percentiles (P90/P99), MAD; log-scale histogram, ECDF; Lorenz/Pareto](../../navigator/#N-DESC-SKEW)** — Spend, income, balances, claim amounts — skewed or heavy-tailed.
    - **[Lognormal or Gamma (compare Q-Q plots and AIC)](../../navigator/#N-DIST-AMT)** — Basket spend, income, claim severity.
    - **[Leakage audit — target, temporal and preprocessing leakage](../../navigator/#N-ML-LEAK)** — AUC suspiciously high (e.g. > 0.95 in credit), or a feature "too predictive".

## 9. Exercises

### Retail · NorthStar

??? example "R1-12 · Basic · How many outliers?"
    **Business framing:** Flag unusual baskets.

    **Deliverable:** Run `retail_outliers_baskets.yaml` on raw data; then count on clean baskets: Tukey 1.5 / 3 × IQR, z > 3, robust z > 3.5.

    ??? success "Expected finding and model answer"
        **Expected:** Clean baskets: Tukey 1.5 → 146, Tukey 3 → 41, z > 3 → 31, robust z > 3.5 → 90 (of 3,163). *(tolerance: exact)*

        **Model answer:** Different rules, very different counts. On skewed data Tukey's 1.5 × IQR flags many ordinary large baskets; the plain z-score is diluted by the inflated SD. 'Outlier' is a decision, not a property.

        **Common wrong answer:** Picking whichever rule gives the answer you wanted.

    **Leader drill:** Which rule would you standardise on for basket monitoring, and why?

??? example "R1-13 · Applied · Can a z-score find the decimal-shift errors?"
    **Business framing:** Before cleaning, the 25 decimal-shift lines sit in 25 baskets.

    **Deliverable:** How many of those baskets each rule catches on raw basket values.

    ??? success "Expected finding and model answer"
        **Expected:** Plain z > 3 catches 19 of 25; robust z > 3.5 catches 25. SD raw 98.53 vs clean 67.58. *(tolerance: exact)*

        **Model answer:** The errors inflate the SD, which raises the z-score bar and hides some of them (masking). Median and MAD are not moved by a few extremes, so the robust score catches them all.

        **Common wrong answer:** Concluding the data are clean because z-scores flagged little.

    **Leader drill:** Why is 'mean ± 3 SD' a poor default in finance and retail data?

??? example "R1-14 · Stretch · Choose a treatment"
    **Business framing:** Decide how basket outliers should be handled for a pricing analysis.

    **Deliverable:** Mean basket under keep, cap at P99, exclude robust outliers, trimmed 10%; share of robust-flagged baskets from the planted bulk buyers.

    ??? success "Expected finding and model answer"
        **Expected:** Keep 50.52, cap P99 47.23, exclude 43.22, trimmed 41.79; about 37.0% of flagged baskets come from 25 bulk-buying customers. *(tolerance: ± 0.1)*

        **Model answer:** The answer moves by over 15% depending on the treatment. Because a large share of extremes are one identifiable segment, the best treatment is to model bulk buyers separately rather than delete or cap them.

        **Common wrong answer:** Silently capping everything at P99.

    **Leader drill:** Write the one-sentence methods note you expect in the appendix.

### Finance · Meridian

??? example "F1-11 · Applied · Transforming income"
    **Business framing:** Income will enter a regression.

    **Deliverable:** Skewness raw, after log, and after Box-Cox (with λ).

    ??? success "Expected finding and model answer"
        **Expected:** Raw 12.21, log 0.45, Box-Cox -0.06 (λ = -0.101). *(tolerance: ± 0.05)*

        **Model answer:** λ close to 0 means Box-Cox is essentially a log transform — choose the log, which is easier to explain (coefficients become % effects).

        **Common wrong answer:** Using Box-Cox with an unexplainable λ when log does the job.

    **Leader drill:** When is a transformation worth the loss of interpretability?

??? example "F1-12 · Stretch · Target encoding can leak"
    **Business framing:** A junior target-encodes a 2,000-level code that contains no information about default.

    **Deliverable:** AUC of the encoded feature computed on all data vs out-of-fold.

    ??? success "Expected finding and model answer"
        **Expected:** In-sample AUC 0.856 vs out-of-fold 0.512. *(tolerance: ± 0.01)*

        **Model answer:** Encoding each row with the default rate of its own category (including itself) leaks the label; with small categories the feature looks highly predictive. Fit encoders inside cross-validation folds.

        **Common wrong answer:** Celebrating a new 'strong' feature.

    **Leader drill:** What question about feature engineering do you add to model reviews?
