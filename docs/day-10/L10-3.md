# L10.3 · Navigator consolidation: scenario sprint

<p class="lesson-meta">Day 10 · Parts A + B · Basic → Advanced 60 min · Leader 45 min · Prerequisites: Navigator trees used on Days 1–9 · Recipes: none</p>

<div class="you-are-here">📍 <b>You are here:</b> Describe / profile the data › No, not yet › <a href="../../navigator/#N-DESC-PROFILE">Profile + data-quality checklist</a> <code>N-DESC-PROFILE</code></div>

**Objectives** — you can: go from a plain-English business question to the right Navigator node in under a minute; name the
assumption check and the fallback; and coach a junior through the map instead of giving them the answer.

## 1. How the sprint works

=== "Basic → Advanced"

    Twenty business questions, one minute each. For each: (1) the data type and question type; (2) the Navigator node; (3) the
    assumption check; (4) the fallback if the check fails. Use the [interactive map](../navigator/index.md) and the
    [scenario atlas](../navigator/scenarios.md). Score yourself with the quiz below, then redo the ones you missed from the map.

=== "Leader"

    Coach, don't tell. For each question a Basic → Advanced colleague brings you, ask in order: *What decision? What's the outcome and its
    type? Is it a comparison, a relationship, a prediction, a forecast, a cause or a check? What would make the answer wrong?* Then
    let them find the node.

## 2. The ten tree roots (memorise these)

| Question type | Start at |
| --- | --- |
| What does the data look like / is it right? | `N-DESC-PROFILE`, `N-DESC-QUALITY` |
| Which distribution? | `N-DIST-*` |
| Are groups different? | `N-TEST-*` |
| Design an experiment | `N-EXP-POWER`, `N-EXP-SRM` |
| How does Y depend on X? | `N-REG-*` |
| Predict / classify | `N-ML-*`, `N-METRIC-*` |
| Group similar items | `N-CLUST-*`, `N-SEG-*` |
| Find the unusual | `N-ANOM-*` |
| Forecast | `N-FCST-*` |
| Did X cause Y? | `N-CAUSAL-*` |
| Is the model still OK? | `N-MON-*` |

## 3. Sprint warm-up (worked)

| Question | Node | Check | Fallback |
| --- | --- | --- | --- |
| "Is average basket higher in Hyper stores than Super?" | `N-TEST-2G-MEAN` | skew, outliers, unequal variance | Welch on log, or permutation |
| "Do complaints vary by branch more than chance?" | `N-TEST-COUNT` | over-dispersion | NB GLM |
| "Which customers will default?" | `N-ML-GBM` vs `N-REG-LOGIT` | leakage, time split | scorecard for explainability |
| "Did the loyalty programme raise spend?" | `N-CAUSAL-DID` | pre-trends; selection | randomised offer |
| "Is the score still working?" | `N-MON-PSI`, `N-MON-CONCEPT` | mix change | recalibrate / rebuild |

<div class="prompt-card" markdown>

??? tip "🛠 Learn by doing — optional vibe-coding lab (15–20 min)"
    1. Pick five questions from the scenario atlas without looking at the answers.
    2. For each, ask Claude Code: "Which Navigator node would you use, what assumption would you check first, and what is the fallback?"
    3. Change one thing: alter the outcome type (e.g. revenue → converted yes/no) and see how the node changes.
    4. Explain it back: teach one question to a partner using only the four coaching questions.

## 5. Scenario matrix

=== "Basic → Advanced"

    | Signal word in the question | Usually |
    | --- | --- |
    | "different", "higher", "compare" | `N-TEST-*` |
    | "drives", "depends", "effect of" (observational) | `N-REG-*` then `N-CAUSAL-DAG` |
    | "caused", "because of", "did it work" | `N-CAUSAL-*` or an experiment |
    | "predict", "score", "who will" | `N-ML-*` |
    | "next month", "how many will" | `N-FCST-*` |
    | "unusual", "suspicious" | `N-ANOM-*` |

=== "Leader"

    | Junior says | You ask |
    | --- | --- |
    | "I ran a t-test" | "On what data type, and did you check skew?" |
    | "The model is 99% accurate" | "What's the base rate and is there leakage?" |
    | "Sales rose after the change" | "Compared with what?" |

## 6. Traps

!!! warning "Traps"
    Choosing the method you know rather than the one the question needs; skipping the assumption check; treating a relationship
    question as a causal one.

## 7. Exercises

### Retail · NorthStar

??? example "R10-9 · Basic · Sprint: stores"
    **Business framing:** 'Is weekly revenue different across the four regions?'

    **Deliverable:** Node, check, fallback.

    ??? success "Expected finding and model answer"
        **Expected:** N-TEST-KG; equal variances (Levene) and clustering by store; Welch ANOVA / mixed model. *(tolerance: —)*

        **Model answer:** Unit of analysis = store-week; clustered.

        **Common wrong answer:** t-tests for every pair.

    **Leader drill:** What decision rides on it?

??? example "R10-10 · Basic · Sprint: forecast"
    **Business framing:** 'How many units of SKU X next month?'

    **Deliverable:** Node, check, fallback.

    ??? success "Expected finding and model answer"
        **Expected:** N-FCST-SEASON (or N-FCST-INTERMITTENT if sparse); baseline seasonal naive; MASE backtest. *(tolerance: —)*

        **Model answer:** Classify demand first (ADI/CV²).

        **Common wrong answer:** ARIMA on intermittent data.

    **Leader drill:** Service-level choice?

??? example "R10-11 · Applied · Sprint: suspicious"
    **Business framing:** 'Are some stores' returns suspicious?'

    **Deliverable:** Node, check, fallback.

    ??? success "Expected finding and model answer"
        **Expected:** N-ANOM-MULTI / robust z on return rates; MAD = 0 fallback; alert budget. *(tolerance: —)*

        **Model answer:** Rates not counts; review capacity.

        **Common wrong answer:** Flagging biggest stores.

    **Leader drill:** What happens to a flagged store?

### Finance · Meridian

??? example "F10-8 · Basic · Sprint: approval test"
    **Business framing:** 'Did the new approval rule raise approvals without raising defaults?'

    **Deliverable:** Node, check, fallback.

    ??? success "Expected finding and model answer"
        **Expected:** N-TEST-2G-PROP if randomised (SRM check); else N-CAUSAL-DID/RDD; guardrail on defaults. *(tolerance: —)*

        **Model answer:** Design determines method.

        **Common wrong answer:** Before/after comparison.

    **Leader drill:** Guardrail threshold?

??? example "F10-9 · Basic · Sprint: claims"
    **Business framing:** 'Do young drivers claim more often?'

    **Deliverable:** Node, check, fallback.

    ??? success "Expected finding and model answer"
        **Expected:** N-TEST-COUNT / N-REG-GLM with exposure offset; over-dispersion → NB. *(tolerance: —)*

        **Model answer:** Rates per exposure-year.

        **Common wrong answer:** Comparing raw claim counts.

    **Leader drill:** Pricing implication?

??? example "F10-10 · Applied · Sprint: churn"
    **Business framing:** 'When do customers leave and why?'

    **Deliverable:** Node, check, fallback.

    ??? success "Expected finding and model answer"
        **Expected:** N-TEST-SURV then Cox; PH check; censoring. *(tolerance: —)*

        **Model answer:** Survival, not averages.

        **Common wrong answer:** Mean churn month of churners.

    **Leader drill:** Retention KPI?

??? example "F10-11 · Applied · Sprint: model health"
    **Business framing:** 'Is the application score still fine?'

    **Deliverable:** Node, check, fallback.

    ??? success "Expected finding and model answer"
        **Expected:** N-MON-PSI + N-MON-CONCEPT + N-METRIC-CALIB; mix; recalibrate/rebuild ladder. *(tolerance: —)*

        **Model answer:** Inputs, performance, calibration.

        **Common wrong answer:** PSI only.

    **Leader drill:** Monitoring cadence?
