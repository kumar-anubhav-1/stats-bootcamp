**Objectives** — you can: take a dataset you have never seen, in a new domain with different column names, and — **without writing code** —
map its columns to recipe roles, run schema and quality checks, adapt existing configs, find what is wrong with the data, answer the
business questions with the right methods, and hand over a reproducible analysis another analyst can rerun.

## 1. The brief

> **SwiftCart** is a quick-commerce start-up delivering groceries from dark stores in four city zones. The COO sends you one file,
> `orders.csv`, and asks: *"What drives basket size and customer ratings, and where should we fix delivery? Amounts are in currency
> units."* You have two hours.

Your instructor gives you the file (it is not in the learner repository). Put it in `data/transfer/orders.csv`.

## 2. How to work

=== "Basic → Advanced"

    1. **Profile and quality first** — copy `retail_profile.yaml` to `toolkit/configs/transfer_profile.yaml`, change only `dataset` and
       `columns`, and run `rcp_profile` then `rcp_quality`. Read the schema report: what doesn't fit the brief?
    2. **Decide grain and units** — one row per order? Are the amounts really in currency units? Check medians against what a grocery
       basket should cost.
    3. **Answer the questions with recipes** — basket size by promo use (`rcp_two_group_test` / `rcp_regression`), rating vs delivery time
       (`rcp_regression`), delivery time by zone (`rcp_multi_group_test`), demand by hour and weekday (`rcp_profile` with a group).
    4. **Navigator** — for each question, write the node you used and why.
    5. **Hand-over** — commit your configs and a one-page readout (L9.7 pyramid).

    Ask Claude Code to *explain* each config change before running it; never edit recipe code.

=== "Leader"

    You review a Basic → Advanced colleague's transfer analysis (or your own quick pass):

    - Did they check grain and units **before** analysis? What changed once they did?
    - Are the configs reusable — could you rerun them on next month's file by changing one path?
    - Is each claim backed by an effect size and uncertainty? Which ones are associations only?
    - What would you tell the COO tomorrow, and what would you test next?

## 3. Navigator

!!! tip "What else could I try?"
    - **[Profile + data-quality checklist](../../navigator/#N-DESC-PROFILE)** — Always first. Types, nulls, uniques, ranges, duplicates, impossible values, grain.
    - **[Data-quality rules (validity, duplicates, reconciliation)](../../navigator/#N-DESC-QUALITY)** — Profiling flagged duplicates, impossible values or unit errors.
    - **[Welch two-sample t-test (+ effect size and CI)](../../navigator/#N-TEST-2G-MEAN)** — Compare average outcome between two independent groups — at the unit that was randomised.
    - **[Linear regression (OLS) with diagnostics](../../navigator/#N-REG-OLS)** — Explain a continuous outcome with several drivers.
    - **[One-way ANOVA (+ Levene); Welch ANOVA + Games-Howell if variances differ; Kruskal-Wallis + Dunn if non-normal](../../navigator/#N-TEST-KG)** — Compare means across 3+ groups (regions, formats).

## 8. Exercises

### Retail · NorthStar

??? example "R10-1 · Basic · Map the columns"
    **Business framing:** SwiftCart orders file.

    **Deliverable:** Column mapping for rcp_profile, rcp_quality, rcp_two_group_test and rcp_regression.

    ??? success "Expected finding and model answer"
        **Expected:** id = order_id; time = order_ts; group = city_zone / dark_store; target = basket amount, items, rating, delivery minutes; promo flag derived from promo_code_used. *(tolerance: —)*

        **Model answer:** Map roles; derive what's missing via config (filters) or ask Claude Code to add a derived column in a prepared copy.

        **Common wrong answer:** Editing recipe code to fit the data.

    **Leader drill:** Which mapping choice would you challenge?

??? example "R10-2 · Basic · Units check"
    **Business framing:** The brief says amounts are in currency units.

    **Deliverable:** Median basket amount; is it plausible for groceries?

    ??? success "Expected finding and model answer"
        **Expected:** A median in the thousands for ~5 items is implausible — amounts are in minor units (÷ 100). *(tolerance: —)*

        **Model answer:** Units checked against domain sense before any statistic.

        **Common wrong answer:** Reporting average basket of 1,800 'currency units'.

    **Leader drill:** Who confirms units with the data owner?

??? example "R10-3 · Applied · Duplicated load"
    **Business framing:** Are all orders unique?

    **Deliverable:** Orders per day; any day with roughly double volume and identical content under new ids.

    ??? success "Expected finding and model answer"
        **Expected:** One day appears twice (same timestamps, baskets, riders; new order_ids) — deduplicate on content, not id. *(tolerance: —)*

        **Model answer:** Duplicates hide behind new keys; check content.

        **Common wrong answer:** Checking only order_id uniqueness.

    **Leader drill:** Which KPIs were overstated?

??? example "R10-4 · Applied · Promo and basket size"
    **Business framing:** Do promo codes grow baskets?

    **Deliverable:** Items per order with vs without a code; effect size and CI.

    ??? success "Expected finding and model answer"
        **Expected:** Positive difference (~+15–20% items) with a tight CI; association only. *(tolerance: —)*

        **Model answer:** Welch on items or regression with zone and hour controls.

        **Common wrong answer:** Calling it causal.

    **Leader drill:** Design the randomised promo test.

??? example "R10-5 · Stretch · Delivery and ratings"
    **Business framing:** Where to fix delivery?

    **Deliverable:** Rating vs delivery minutes (slope); minutes by zone (k-group test); peak hours.

    ??? success "Expected finding and model answer"
        **Expected:** Ratings fall with minutes beyond ~15; zone Z4 slowest (~6 min); evening slower; Fri/Sat peak. *(tolerance: —)*

        **Model answer:** Regression for the slope; Welch ANOVA + Games-Howell for zones; ratings missing for ~45% (check MNAR).

        **Common wrong answer:** Averaging ratings without considering who rates.

    **Leader drill:** Investment case for Z4?

### Finance · Meridian

??? example "F10-1 · Basic · Transfer reuse review"
    **Business framing:** A colleague's SwiftCart configs.

    **Deliverable:** Checklist to review reusable configs.

    ??? success "Expected finding and model answer"
        **Expected:** One path to change; documented column mapping; filters explicit; outputs dated; schema report read; regression baseline saved. *(tolerance: —)*

        **Model answer:** Reproducible by someone else next month.

        **Common wrong answer:** Hard-coded values in prompts only.

    **Leader drill:** Would you sign it off?

??? example "F10-2 · Applied · Ratings missingness"
    **Business framing:** Only some orders are rated.

    **Deliverable:** Test whether rating presence depends on delivery time or cancellation.

    ??? success "Expected finding and model answer"
        **Expected:** Compare delivery minutes for rated vs unrated; treat ratings as possibly MNAR; report the bias direction. *(tolerance: —)*

        **Model answer:** L1.3 missingness logic transfers.

        **Common wrong answer:** Averaging available ratings as 'customer satisfaction'.

    **Leader drill:** What would you add to the app?
