**Objectives** — you can: take a dataset you have never seen, in a new domain with different column names, and — **without writing code** —
map its columns to recipe roles, run schema and quality checks, adapt existing configs, find what is wrong with the data, answer the
business questions with the right methods, and hand over a reproducible analysis another analyst can rerun.

## 1. The brief

> **SwiftCart** is a quick-commerce start-up delivering groceries from dark stores in four city zones. The COO sends you one file,
> `orders.csv`, and asks: *"What drives basket size and customer ratings, and where should we fix delivery? Amounts are in currency
> units."* You have two hours.

Your instructor gives you the file (it is not in the learner repository). Put it in `data/transfer/orders.csv`.

## 2. How to work

=== "Basic → Advanced"

    1. **Profile and quality first** — copy `retail_profile.yaml` to `toolkit/configs/transfer_profile.yaml`, change only `dataset` and
       `columns`, and run `rcp_profile` then `rcp_quality`. Read the schema report: what doesn't fit the brief?
    2. **Decide grain and units** — one row per order? Are the amounts really in currency units? Check medians against what a grocery
       basket should cost.
    3. **Answer the questions with recipes** — basket size by promo use (`rcp_two_group_test` / `rcp_regression`), rating vs delivery time
       (`rcp_regression`), delivery time by zone (`rcp_multi_group_test`), demand by hour and weekday (`rcp_profile` with a group).
    4. **Navigator** — for each question, write the node you used and why.
    5. **Hand-over** — commit your configs and a one-page readout (L9.7 pyramid).

    Ask Claude Code to *explain* each config change before running it; never edit recipe code.

=== "Leader"

    You review a Basic → Advanced colleague's transfer analysis (or your own quick pass):

    - Did they check grain and units **before** analysis? What changed once they did?
    - Are the configs reusable — could you rerun them on next month's file by changing one path?
    - Is each claim backed by an effect size and uncertainty? Which ones are associations only?
    - What would you tell the COO tomorrow, and what would you test next?

## 5. Rubric (each criterion scored 1–5; pass ≥ 3 on every criterion)

| Criterion | 5 looks like |
| --- | --- |
| Correctness | data issues found and fixed before analysis; methods fit the data; numbers verified |
| Assumptions | grain, units, independence and confounding stated and checked |
| Interpretation | effect sizes with CIs; association vs causation kept separate |
| Action | concrete recommendations with owners and a follow-up test |
| Clarity & reuse | pyramid readout; configs committed and rerunnable by changing one path |

## 6. Scenario matrix

=== "Basic → Advanced"

    | You notice | Do |
    | --- | --- |
    | a column name you don't recognise | ask Claude Code what it might mean; confirm with the data dictionary or owner |
    | amounts look 100× too big or small | check units before any statistic |
    | the same day appears twice as often as others | check for a duplicated load |
    | a recipe errors on a role | read the schema report — it suggests columns |

=== "Leader"

    | Review question | Good answer |
    | --- | --- |
    | "How do you know the data are right?" | the checks run and what they found |
    | "Is promo causing bigger baskets?" | association; propose a randomised promo test |
    | "Where do we fix delivery?" | zone with the slowest times and the rating impact per minute |
