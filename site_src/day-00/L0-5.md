# L0.5 · Data safety and anonymisation

<p class="lesson-meta">Day 0 · Basic → Advanced 30 min · Leader 20 min · Prerequisites: L0.1</p>

**Objectives** — by the end you can: decide which data may be used in which tool; anonymise a file before analysis with Claude
Code; and explain why removing names is not the same as anonymising.

## 1. Business question

> "I want to try today's technique on our real customer file. **What am I allowed to do, and how do I make the file safe first?**"

## 2. Concept

=== "Basic → Advanced"

    **Three rules that are never broken**

    1. **Only approved data in approved environments.** Your company decides which tools may process which data classes. The
       course data is synthetic and safe anywhere; company data is not.
    2. **Never paste confidential data into a chat or tool that is not approved for it** — not even "just ten rows to show the format".
    3. **Minimise.** Use only the columns and rows the question needs.

    **Anonymisation techniques**

    | Technique | What it does | Example |
    | --- | --- | --- |
    | **Pseudonymisation** | Replace identifiers with a salted hash; keep the key separately | `C00123` → `a91f…` |
    | **Generalisation** | Make values coarser | age 37 → `35-44`; postcode → region |
    | **Suppression** | Remove rare or risky values/rows | drop free-text notes; suppress groups with < 5 people |
    | **Noise / rounding** | Perturb numbers slightly | income rounded to nearest 1,000 |
    | **Synthetic data** | Generate artificial data with similar patterns | the course datasets |

    **Why removing names is not enough.** Combinations of ordinary fields (age band + postcode + household size + a rare product)
    can single out a person. **k-anonymity** asks: is every combination of identifying fields shared by at least *k* people? If a
    combination appears once, that person may be re-identified.

    **Pseudonymised data is still personal data** under most privacy laws (the key can reverse it). Treat it accordingly.

=== "Leader"

    **Refresh:** approved data in approved tools; minimise; pseudonymise + generalise + suppress; check k-anonymity; pseudonymised ≠ anonymous.

    **Your accountability as a leader**

    - Publish a **data-class × tool matrix** (public / internal / confidential / restricted × which AI tools and environments).
    - Require an **anonymisation step in the pipeline** (a recipe), not a manual habit.
    - **Protected attributes** (e.g. the `protected_group` field in the bank data) are used only to *monitor* fairness, never as model inputs.
    - Ask for a **re-identification check** (smallest group size) before any extract leaves the secure environment.

    !!! tip "Coaching card"
        When a junior asks "can I use this file with the AI?", answer with two questions: *"What data class is it?"* and
        *"Which environment are you in?"* — then point to the matrix. Make the decision repeatable, not personal.
