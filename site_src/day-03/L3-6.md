## 2. Concept

=== "Basic → Advanced"

    ### 2.1 Effect sizes — the number the decision needs

    | Measure | Use for | Example from our data |
    | --- | --- | --- |
    | Difference in business units | always | challenger cure rate {{ a.d3_f16_cure_ch }}% vs champion {{ a.d3_f16_cure_cp }}%: **+{{ a.d3_f16_diff }} pp** (95% CI {{ a.d3_f16_ci[0] }} – {{ a.d3_f16_ci[1] }}) |
    | Relative risk (RR) | rates | {{ a.d3_f16_rr }} (cure is {{ ((a.d3_f16_rr - 1) * 100) | round(0) | int }}% more likely) |
    | Odds ratio (OR) | logistic models, case-control | {{ a.d3_f16_or }} — larger than RR when the outcome is common |
    | Number needed to treat (NNT) | operations | {{ a.d3_f16_nnt }} accounts on the challenger per extra cure |
    | Cohen's d / Hedges' g | standardised mean difference | Hair Care test g = {{ a.l34_hedges_g }} (L3.4) |
    | η² / Cramér's V | k groups / tables | region η² = {{ a.d3_eta2 }}; employment V = {{ a.d3_emp_v }} (L3.5) |

    Cohen's benchmarks (d 0.2 small, 0.5 medium, 0.8 large) are context-free; a 3 pp cure-rate gain worth millions is "small" by
    Cohen and huge by the P&L.

    ### 2.2 Power — the chance of detecting a real effect

    Four quantities are linked: **α**, **power** (1 − β), **effect size** and **n**. Fix three and the fourth follows. Variability comes
    from your data: the store growth index has SD **{{ a.d3_gi_sd }}** (pooled within arms of the Hair Care test).

    **Stores per arm for 80% power, α = 0.05:**

    | Lift to detect | 5% | 8% | 10% | 12% | 15% | 20% |
    | --- | --- | --- | --- | --- | --- | --- |
    | Stores per arm | {{ a.d3_stores_per_arm[5] }} | {{ a.d3_stores_per_arm[8] }} | {{ a.d3_stores_per_arm[10] }} | {{ a.d3_stores_per_arm[12] }} | {{ a.d3_stores_per_arm[15] }} | {{ a.d3_stores_per_arm[20] }} |

    With the 20 + 20 stores we have, the **MDE is {{ a.d3_mde_20 }}%**. Power for a true lift of 5% is only
    **{{ a.d3_power_20_at[5] }}%**; for 12%, {{ a.d3_power_20_at[12] }}%. A 5% effect would usually be missed — and the chain has only
    40 stores, so a 5% test is impossible as designed. Options: longer test window, better baseline adjustment (CUPED, L4.2), or accept
    a larger MDE.

    **Halving the effect quadruples the sample** (n ∝ 1/effect²).

    ### 2.3 Proportions and unequal splits

    Champion cure rate ≈ {{ a.d3_f16_cure_cp }}%. To detect +3 pp (Cohen's h = {{ a.d3_cohen_h_3pp }}) at 80% power with an
    **80/20** champion/challenger split: **{{ a.d3_n_challenger_3pp | n }} challenger + {{ a.d3_n_champion_3pp | n }} champion =
    {{ a.d3_n_total_3pp | n }} accounts**. A 50/50 split would need about {{ a.d3_n_total_3pp_5050 | n }} — unequal splits are safer
    for the business but cost sample.

    | Improvement to detect | +2 pp | +3 pp | +5 pp | +8 pp |
    | --- | --- | --- | --- | --- |
    | Accounts needed (80/20) | {{ a.d3_prop_curve[2] | n }} | {{ a.d3_prop_curve[3] | n }} | {{ a.d3_prop_curve[5] | n }} | {{ a.d3_prop_curve[8] | n }} |

    The actual test (F16) had {{ a.d3_f16_n_ch }} challenger and {{ a.d3_f16_n_cp | n }} champion accounts: power for a 3 pp effect was
    only **{{ a.d3_power_actual_3pp }}%**. It found an effect because the true effect was about 6 pp — lucky, not well designed.

    ### 2.4 Clustering: the design effect

    If stores are randomised but you analyse store-weeks, the weeks within a store are highly alike. Intra-class correlation of weekly
    Hair Care units within stores: **ICC = {{ a.d3_icc_weeks }}**. Design effect for 16 weeks per store:

    $$\text{DEFF} = 1 + (m - 1) \times \text{ICC} = {{ a.d3_deff_16 }}$$

    So 640 store-weeks (40 stores × 16) carry the information of about **{{ a.d3_eff_n_640 }}** independent observations. Plan and
    analyse at the store.

    ### 2.5 Under-powered "no effect"

    L3.4 found no significant default difference for high-net-worth customers (n = 241, Fisher p = {{ a.l34_hni_fisher_p }}). Power to
    detect a true 6% vs 4% default rate with that n was **{{ a.d3_hni_power }}%**. The test could not have found it; "HNI customers are
    no riskier" is not a supported conclusion. Report the MDE whenever a test is not significant.

=== "Leader"

    !!! abstract "Refresh"
        Effect size is what the decision needs; power is the probability the design detects the effect you care about. Size tests
        *before* running them, on the unit that was randomised. A non-significant under-powered test is uninformative.

    **Judgement points**

    - **Set the MDE from economics.** "What is the smallest lift that pays for a rollout?" — then size the test for it. If the
      required sample is impossible, change the design or don't run the test.
    - **Never accept post-hoc "observed power".** It is a restatement of the p-value. Power is a design property.
    - **Unequal splits are a risk choice.** 80/20 protects the business but needs ~{{ ((a.d3_n_total_3pp / a.d3_n_total_3pp_5050 - 1) * 100) | round(0) | int }}%
      more accounts for the same power.
    - **Cluster designs need cluster thinking.** A vendor quoting "power from 25,000 transactions" for a 40-store test is wrong by a
      factor of the design effect.

    !!! tip "Coaching card"
        Before approving any test, ask for: MDE, power, unit of randomisation, n per arm, test duration and the decision rule.

| Section | Read as |
| --- | --- |
| Design line | α, sides, power, ratio and the **unit** |
| From data | mean/SD or baseline rate the plan rests on (check it is a pre-treatment or control estimate) |
| Sample-size table | units per arm and total for each effect |
| With the sample you have | MDE and achieved power for the real n |
| Power curve | how quickly power rises with n for each effect |

## 6. Scenario matrix

=== "Basic → Advanced"

    | Situation | Effect size to report | Planning tool |
    | --- | --- | --- |
    | means, two groups | difference + d/g | t-test power |
    | rates | risk difference, RR, OR, NNT | proportions power (Cohen's h) |
    | k groups | η² / Cramér's V | ANOVA / chi-square power |
    | randomised clusters | difference at cluster level | power with design effect |

    | Team says | You ask | Norm |

    | "observed power was 35%" | — ignore | power is planned, not computed afterwards |
    | "let's test 8 variants on 40 stores" | per-variant n and MDE | sample shrinks per arm |

## 10. Recap

Report effects in business units; size tests from data before running; MDE ∝ 1/√n; plan at the randomised unit; never read an
