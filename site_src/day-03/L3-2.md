## 2. Concept

=== "Basic → Advanced"

    ### 2.1 The bootstrap: let the data simulate its own uncertainty

    1. Treat your sample as a stand-in for the population.
    2. Draw a new sample of the same size **with replacement** (some rows twice, some not at all).
    3. Compute the statistic (median, ratio, percentile, anything).
    4. Repeat thousands of times. The spread of those values is the sampling distribution; its 2.5th and 97.5th percentiles give a
       95% **percentile interval**. (BCa intervals adjust for bias and skew — use them when the recipe offers them.)

    | Statistic | Estimate | 95% bootstrap CI | Why bootstrap |
    | --- | --- | --- | --- |
    | Median spend per customer ({{ a.d3_cust_n | n }} customers) | {{ a.d3_cust_median }} | {{ a.d3_cust_median_ci[0] }} – {{ a.d3_cust_median_ci[1] }} | no simple SE formula for a median |
    | Margin rate (margin ÷ revenue) | {{ a.d3_margin_pct }}% | {{ a.d3_margin_ci[0] }} – {{ a.d3_margin_ci[1] }}% | ratio of two random totals |

    ### 2.2 Resample the right unit

    The bootstrap assumes the things you resample are independent. Lines from the same store share the store's prices, mix and
    customers. Mean revenue per line = {{ a.d3_line_mean }}:

    | Resampling unit | SE of mean line revenue |
    | --- | --- |
    | lines (wrong: treats lines as independent) | {{ a.d3_se_lines }} |
    | stores (right: whole stores resampled — a *cluster* bootstrap) | {{ a.d3_se_stores }} |

    The honest SE is **{{ a.d3_se_ratio_store_line }}× larger**. Any CI or test built on lines would be far too confident.

    ### 2.3 The permutation test: what if the labels didn't matter?

    H0: branch makes no difference to default. If that were true, shuffling the branch labels would not change anything systematic.

    1. Compute the observed difference: {{ a.d3_perm_br_b }} {{ a.d3_perm_rate_b }}% vs {{ a.d3_perm_br_a }} {{ a.d3_perm_rate_a }}% →
       **{{ a.d3_perm_diff_pp }} pp**.
    2. Pool the {{ (a.d3_perm_n_a + a.d3_perm_n_b) | n }} accounts, shuffle the labels, recompute the difference. Repeat 10,000 times.
    3. p = share of shuffles at least as extreme as the observed difference = **{{ a.d3_perm_p }}**.

    The chi-square test gives p = {{ a.d3_chi2_p_branches }} — the two agree because n is large. The difference is noise.

    ### 2.4 When resampling beats formulas — and when it doesn't

    | Use resampling | Prefer a formula or a model |
    | --- | --- |
    | medians, ratios, percentiles, Gini, any custom metric | simple means and proportions with large n (same answer, faster) |
    | skewed data with modest n | very small n (< 15): the bootstrap cannot invent information |
    | small randomised experiments (permutation is exact) | clustered or time-series data unless you resample clusters/blocks |
    | checking a formula's assumptions | extreme quantiles (P99 of 300 points) |

=== "Leader"

    !!! abstract "Refresh"
        The bootstrap resamples your data to measure uncertainty of any statistic. A permutation test shuffles labels to see how
        unusual the observed difference is under "no effect". Both depend on resampling the **independent unit**.

    **Judgement points**

    - **"We bootstrapped it" is not a quality stamp.** Ask *what* was resampled. Lines instead of stores understated uncertainty
      {{ a.d3_se_ratio_store_line }}-fold here.
    - **Permutation tests are ideal for small store tests.** L3.4 used one: with 20 v 20 stores the shuffle distribution is exact
      and assumption-light (p = {{ a.l34_perm_p }}).
    - **Fix the seed and the number of resamples** so results reproduce — audit and model validation will ask.

    !!! tip "Coaching card"
        Ask: *"What did you resample, how many times, with what seed — and does the classical test agree?"* Disagreement is a clue to
        skew or clustering, not a reason to pick the smaller p-value.

## 5. Output anatomy — a bootstrap result

| Element | Read as |
| --- | --- |
| Resampling unit | must be the independent unit (customer, basket, store, account) |
| B (resamples), seed | ≥ 2,000 for intervals; seed for reproducibility |
| Bootstrap distribution plot | lumpy or multi-modal → statistic unstable (median of few values) |
| Percentile vs BCa interval | close → fine; far apart → skew/bias, prefer BCa |
| Permutation p | share of shuffles as extreme as observed; minimum is 1/(B + 1) |

## 6. Scenario matrix

=== "Basic → Advanced"

    | Question | Method |
    | --- | --- |
    | CI for a median, ratio, percentile | bootstrap (percentile or BCa) |
    | Data clustered in stores/branches | cluster bootstrap (resample clusters) |
    | Small randomised test, any statistic | permutation test |
    | Large n, mean or proportion | classical test (resampling agrees) |

=== "Leader"

    | Claim | Check | Norm |
    | --- | --- | --- |
    | "bootstrap CI on 25,000 lines" | resampling unit | resample stores/customers |
    | "permutation p = 0.000" | number of shuffles | report p < 1/(B + 1) |
    | "branch X worse" | permutation/chi-square p and CI | most branch gaps are noise or mix |
