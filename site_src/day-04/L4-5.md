    ### 2.2 Cluster tests: analyse at the cluster

    Stores were randomised, so the store is the unit. Line-level panel data had only {{ a.l34_panel_lines_test }} and
    {{ a.l34_panel_lines_ctrl }} Hair Care lines in the test window and treat lines as independent — wrong on both counts (L3.4). CUPED
    on store-level pre-period units shrinks the SE {{ a.d4_store_se_ratio }}-fold (L4.2).

    ### 2.3 The decision memo (one page)

    1. **Decision requested** and recommendation.
    2. **What we tested**, unit, dates, sample sizes, pre-registered primary metric.
    3. **Hygiene:** SRM, balance, data issues found.
    4. **Result:** effect in business units with CI; probability of exceeding the threshold (L4.3).
    5. **Guardrails and risks.**
    6. **Money:** expected annual value with a range (Monte Carlo, L2.5).
    7. **Next steps:** rollout plan, holdout, monitoring metric and review date.

=== "Leader"

    !!! abstract "Refresh"
        A test is only as good as its weakest step: design, hygiene, analysis unit, guardrails, decision rule. Your job is to check
        the chain and make the call — including when the evidence is good but not decisive.

    **Judgement points**

    - **Hair Care:** effect is real (CI excludes 0) and probably above the 10% rollout threshold, but not certainly. Roll out with a
      **holdout of a few stores** to keep measuring; the cost of being wrong is modest and reversible.
    - **Collections:** the effect is solid despite the under-powered design (the true effect was larger than planned). Replace the
      champion, keep a 10% holdout of the old script for a quarter to confirm, and size the next test properly.
    - **Guardrails can veto.** Had complaints risen significantly, the cure-rate gain would not justify the switch without a
      conversation with conduct risk.

    !!! tip "Coaching card"
        Have the junior present the memo in five minutes; your questions: *SRM? unit? CI vs threshold? guardrails? holdout?*

## 5. Output anatomy — the decision memo

| Section | Must contain |
| --- | --- |
| Recommendation | one sentence, first line |
| Evidence | effect + CI + unit + n |
| Hygiene | SRM p, balance, data caveats |
| Guardrails | each with CI; any breach explained |
| Value | annualised impact range |
| Plan | rollout, holdout, monitoring, review date |

## 6. Scenario matrix

=== "Basic → Advanced"

    | Result pattern | Recommendation |
    | --- | --- |
    | CI above threshold, guardrails fine | ship (holdout optional) |
    | CI above 0, threshold inside CI | ship with holdout / extend |
    | CI includes 0, MDE large | inconclusive — redesign (CUPED, more units) |
    | guardrail breach | don't ship; investigate |
    | SRM | stop; fix; re-run |

=== "Leader"

    | Pressure | Response | Norm |
    | --- | --- | --- |
    | "just roll it out everywhere" | keep a holdout | measure post-launch effect |
    | "the test was small, so ignore it" | read CI and MDE | evidence, not size alone |
    | "complaints are noise" | show CI | guardrail pre-agreed |
