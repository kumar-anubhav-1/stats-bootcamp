## 2. Concept

=== "Basic → Advanced"

    ### 2.1 Prior × likelihood → posterior

    - **Prior:** what we believed before the data (from history, other tests, expert judgement).
    - **Likelihood:** how probable the observed data are for each possible value.
    - **Posterior:** updated belief = prior × likelihood (normalised). With more data the likelihood dominates.

    For rates, the **Beta–Binomial** pair makes this arithmetic: prior Beta(α, β) + k successes in n trials → posterior
    Beta(α + k, β + n − k). Beta(α, β) behaves like "α successes and β failures already seen".

    ### 2.2 Bayesian A/B on the e-coupon (clean data)

    Uniform priors Beta(1, 1) for each arm, 200,000 posterior draws:

    | Quantity | Value | Meaning |
    | --- | --- | --- |
    | P(treatment > control) | **{{ a.d4_bayes_p_better }}%** | probability the coupon is better, given data and prior |
    | Posterior mean lift | {{ a.d4_bayes_mean_pp }} pp | |
    | 95% credible interval | {{ a.d4_bayes_ci_pp[0] }} to {{ a.d4_bayes_ci_pp[1] }} pp | 95% probability the lift lies here (given the model) |
    | P(lift > 1 pp) | {{ a.d4_bayes_p_gt1pp }}% | probability of clearing the practical threshold |
    | Expected loss if we ship | {{ a.d4_bayes_loss_t_pp }} pp | average conversion we give up if the coupon is actually worse |
    | Expected loss if we keep control | {{ a.d4_bayes_loss_c_pp }} pp | what we forgo by not shipping |

    **Decision rule:** ship when expected loss of shipping is below a pre-agreed "threshold of caring" (e.g. 0.1 pp).

    With flat priors the credible interval matches the confidence interval ({{ a.d4_clean_ci[0] }} to {{ a.d4_clean_ci[1] }}); the
    *interpretation* differs. A credible interval is a probability statement about the parameter; a confidence interval is a
    statement about the procedure (L3.1).

    ### 2.3 Priors matter when data are thin

    **Sceptical prior.** Past coupon tests rarely moved conversion by more than ~1 pp: prior on the lift centred at +0.2 pp, SD 0.4 pp.
    Posterior mean **{{ a.d4_bayes_skept_mean_pp }} pp** (95% interval {{ a.d4_bayes_skept_ci_pp[0] }} to {{ a.d4_bayes_skept_ci_pp[1] }}),
    P(better) {{ a.d4_bayes_skept_p_better }}%. A sceptical prior shrinks surprising results — a defence against the winner's curse,
    at the price of being slow to believe genuinely big effects. **State and justify priors before seeing data; show sensitivity to them.**

    ### 2.4 A new segment with few accounts

    Students acquired through the online partner in 2025Q3: **{{ a.d4_new_k }} defaults out of {{ a.d4_new_n }}** = {{ a.d4_new_raw_pct }}%
    (Wilson CI {{ a.d4_new_wilson[0] }} – {{ a.d4_new_wilson[1] }}%). Prior: historical student default rate {{ a.d4_prior_rate_pct }}%,
    weighted as {{ a.d4_prior_eff_n }} accounts' worth of evidence.

    | | Default rate | Interval |
    | --- | --- | --- |
    | Prior (history) | {{ a.d4_prior_rate_pct }}% | — |
    | Data only | {{ a.d4_new_raw_pct }}% | {{ a.d4_new_wilson[0] }} – {{ a.d4_new_wilson[1] }}% |
    | **Posterior** | **{{ a.d4_post_mean_pct }}%** | {{ a.d4_post_ci_pct[0] }} – {{ a.d4_post_ci_pct[1] }}% |

    P(default rate > 10%) = **{{ a.d4_post_p_gt10 }}%**. Even after shrinkage towards history, this segment is far riskier than past
    students — the latest vintages are different (L3.3, L9.6). The prior weight is a judgement: 100 accounts' worth says "history is
    relevant, but not decisive". Show results for other weights.

    ### 2.5 Beyond conjugate pairs

    For models without neat formulas (hierarchical store effects, many parameters) probabilistic-programming tools such as PyMC or
    Stan draw from the posterior by simulation (MCMC). Ask Claude Code for a PyMC model only when the conjugate or normal approximation
    is not enough, and always check convergence diagnostics (R-hat ≈ 1, effective sample size).

=== "Leader"

    !!! abstract "Refresh"
        Bayesian readouts answer the question executives ask — "how likely is it better, and what do we risk?" — at the cost of
        stating a prior. With lots of data, Bayesian and frequentist answers agree; with little data, the prior matters and must be
        defended.

    **Judgement points**

    - **Use P(better) and expected loss in decision memos.** "{{ a.d4_bayes_p_better }}% likely better; shipping risks at most
      {{ a.d4_bayes_loss_t_pp }} pp on average" is clearer than "p = {{ a.d4_clean_p }}".
    - **Bayesian does not fix bad data.** The SRM-broken test gives a misleading posterior too.
    - **Priors are governance.** Agree default priors per test type in advance; never choose them after seeing results.
    - **Small segments need shrinkage.** New products, branches and segments should be planned on posterior estimates, not on
      their first raw rate.

    !!! tip "Coaching card"
        Ask: *"What prior did you use, why, and how does the conclusion change with a flat prior and a sceptical one?"*

## 5. Output anatomy — Bayesian section

| Element | Read as |
| --- | --- |
| P(treatment better) | not a p-value; 50% = no idea, 99% = strong evidence |
| credible interval | 95% probability range for the lift under the model and prior |
| expected loss if ship / keep | average regret of each choice; ship when "ship" loss is tiny |
| prior statement | must be shown; flat priors ≈ frequentist answer |

## 6. Scenario matrix

=== "Basic → Advanced"

    | Situation | Approach |
    | --- | --- |
    | large A/B test, no strong prior | flat prior — same answer as frequentist, better language |
    | many similar past tests | informative / sceptical prior from their results |
    | tiny segment, relevant history | Beta prior with modest weight (shrinkage) |
    | complex hierarchical model | PyMC/Stan, with diagnostics |

=== "Leader"

    | Team says | You ask | Norm |
    | --- | --- | --- |
    | "95% chance B is better" | prior? data quality (SRM)? | priors pre-agreed |
    | "new segment defaults at 20%" | n and shrunk estimate | plan on posterior |
    | "Bayesian means we can peek" | expected loss rule still needed | stopping rules still matter |
