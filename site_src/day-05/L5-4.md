## 2. Concept

=== "Basic → Advanced"

    ### 2.1 Overfitting

    A model with many parameters relative to the data learns noise. Training fit improves; new-data performance falls.

    **Retail.** Beverages log-units model with {{ a.d5_reg_p }} features (store dummies, promo, stock-outs, temperature, holiday and
    16 pure-noise columns). Train on weeks ≤ 78, test on weeks 79–104:

    | Training data | Model | Train R² | Test R² |
    | --- | --- | --- | --- |
    | 78 weeks ({{ (a.d5_bev_n * 78 / 104) | round(0) | int | n }} rows) | OLS | {{ a.d5_r2_ols_tr }} | {{ a.d5_r2_ols_te }} |
    | | Ridge / Lasso (CV) | — | {{ a.d5_r2_ridge_te }} / {{ a.d5_r2_lasso_te }} |
    | **2 weeks ({{ a.d5_n8 }} rows)** | OLS | **{{ a.d5_r2_ols8_tr }}** | **{{ a.d5_r2_ols8_te }}** |
    | | Lasso (CV) | — | **{{ a.d5_r2_las8_te }}** ({{ a.d5_las8_kept }} features kept, {{ a.d5_las8_noise_kept }} of 16 noise) |

    With plenty of data (rows ≫ features) OLS is fine and regularisation changes nothing. With {{ a.d5_n8 }} rows and
    {{ a.d5_reg_p }} features OLS memorises the training weeks (R² {{ a.d5_r2_ols8_tr }}) and fails on new weeks; the lasso's penalty
    holds up far better. Note that the lasso still kept some noise columns — it is a regulariser, not an oracle.

    {{ chart("overfit", "Drag the degree: training error keeps falling, held-out error falls then explodes — overfitting you can see.") }}

    ### 2.2 The penalties

    | Method | Penalty | Effect | Use when |
    | --- | --- | --- | --- |
    | Ridge (L2) | λ Σβ² | shrinks all coefficients; keeps correlated ones together | many correlated predictors (income + limit) |
    | Lasso (L1) | λ Σ\|β\| | shrinks and sets some to exactly 0 | feature selection, sparse models |
    | Elastic net | mix | selection + stability with correlated groups | many correlated candidates |

    Standardise predictors first (the recipes and scikit-learn pipelines do). λ is chosen by **cross-validation** — shuffle the folds
    unless the data are time-ordered (then use time-based folds, L6.4).

    ### 2.3 Finance: 40 candidates (20 real, 20 noise), 4,000 training accounts

    | Model | Features | Noise kept | Test AUC |
    | --- | --- | --- | --- |
    | Unpenalised logistic | {{ a.d5_f_p }} | all | {{ a.d5_f_auc_full_te }} (train {{ a.d5_f_auc_full_tr }}) |
    | Lasso, best CV AUC | {{ a.d5_f_l1best_kept }} | {{ a.d5_f_l1best_noise_kept }} | {{ a.d5_f_auc_l1best_te }} |
    | Lasso, 1-SE rule | {{ a.d5_f_l1_kept }} | {{ a.d5_f_l1_noise_kept }} | {{ a.d5_f_auc_l1_te }} |

    The unpenalised model loses AUC from train to test (overfitting); the lasso with the best CV penalty keeps a handful of real
    variables, drops the noise and predicts at least as well. The **1-SE rule** (the simplest model within one standard error of the
    best) gives an even smaller model at almost no cost: top drivers {{ a.d5_f_l1_top | join(", ") }}.

    ### 2.4 Information criteria

    | Beverages model (full data, store FE) | k | AIC | BIC |
    | --- | --- | --- | --- |
    {% for k, v in a.d5_ic.items() %}| {{ k }} | {{ v.k }} | {{ v.aic | n }} | {{ v.bic | n }} |
    {% endfor %}

    Lower is better. BIC penalises extra parameters more (log n per parameter); both prefer adding promotions and stock-outs. The
    region × temperature interaction also lowers AIC and BIC — but the planted temperature effect is the same everywhere, so check the
    size of the gain and whether it holds out of sample before believing it.

=== "Leader"

    !!! abstract "Refresh"
        Overfitting = learning noise. Regularisation trades a little bias for much less variance; cross-validation chooses how much.
        With lots of data relative to features it barely matters; with many features or few rows it matters a lot.

    **Judgement points**

    - **Training fit is not evidence.** Ask for held-out (and out-of-time) performance every time.
    - **Parsimony has business value:** fewer variables = cheaper data, easier monitoring, clearer adverse-action reasons. Prefer the
      1-SE model when the loss is negligible.
    - **Lasso selection is not causal.** Correlated drivers are dropped almost at random; don't read "not selected" as "doesn't
      matter".

    !!! tip "Coaching card"
        Ask: *"Train vs test performance? How was λ chosen — folds shuffled or by time? What would a 1-SE model drop?"*

## 6. Scenario matrix

=== "Basic → Advanced"

    | Situation | Approach |
    | --- | --- |
    | rows ≫ features | OLS/logistic fine; regularisation optional |
    | many features, few rows | lasso / elastic net |
    | correlated groups | ridge or elastic net |
    | compare a few nested models | AIC/BIC or likelihood-ratio test |
    | predictive use | held-out / cross-validated error decides |

=== "Leader"

    | Claim | Question | Norm |
    | --- | --- | --- |
    | "R² 0.99 on training" | test R²? | out-of-sample validation |
    | "lasso dropped income, so income doesn't matter" | correlated with limit? | selection ≠ causality |
    | "AIC improved by 3" | out-of-sample gain? | small ΔAIC on large n means little |

## 7. Planted traps and reuse drill

!!! warning "Traps"
    Unshuffled CV folds on store-sorted data drop whole stores (an easy way to get a nonsensical λ); F06 collinearity makes lasso
    pick income *or* limit arbitrarily.

**Reuse drill:** repeat the finance screen with elastic net (l1_ratio 0.5) — does it keep income and limit together?
