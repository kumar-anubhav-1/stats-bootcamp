**Objectives** — you can: classify a missing-data pattern as MCAR, MAR or (possibly) MNAR using evidence; test missingness at
the right unit; choose a treatment (deletion, simple or model-based imputation, missing indicator); and recognise silent row loss.

## 1. Business question

=== "Retail"

    > "Marketing wants an age profile of shoppers and a household-size segmentation. **Can we trust the fields that are only partly filled?**"

=== "Finance"

    > "Income is missing for {{ a.d1_inc_miss_pct }}% of accounts. **Can the scorecard just drop them?**"

## 2. Concept

=== "Basic → Advanced"

    ### 2.1 Three mechanisms

    | Mechanism | Meaning | Course example | Consequence of dropping rows |
    | --- | --- | --- | --- |
    | **MCAR** — missing completely at random | Missingness unrelated to anything | Temperature lost for random region-days (R04) | Less data, no bias |
    | **MAR** — missing at random *given observed data* | Explained by fields you have | Age missing far more for non-members (R05) | Bias unless you condition on the explaining field |
    | **MNAR** — missing not at random | Depends on the missing value itself | Large households skip household size (R06); risky applicants skip income (F02) | Bias you cannot fix by conditioning |

    ### 2.2 How to diagnose

    1. **Rates by segment.** Compare the missing rate across fields you observe (chi-square for categories, Mann-Whitney for numbers).
       If it varies → *not MCAR*.
    2. **Test at the right unit.** Temperature goes missing per **region-day**. Tested across individual transaction lines, a chance
       difference between regions gives p ≈ {{ a.d1_temp_miss_region_p_line }}; tested across {{ a.d1_temp_regiondays | n }}
       region-days, p = {{ a.d1_temp_miss_region_p }}. Lines in the same region-day are not independent.
    3. **Compare outcomes.** Do rows with the value missing behave differently? Customers missing household size have
       {{ a.d1_hh_lines_ratio }}× as many lines per basket — even though every missingness test passed. That is the MNAR signature.

    !!! note "Tests can rule MCAR out, never in"
        Little's MCAR test and the segment tests above can only show that data are *not* MCAR. MNAR can never be proven from the data
        alone — you need outcome comparisons, business knowledge, or follow-up data.

    ### 2.3 Treatments

    | Treatment | When acceptable | Risk |
    | --- | --- | --- |
    | **Listwise deletion** (drop incomplete rows) | MCAR, small share | Silent row loss; bias otherwise |
    | **Pairwise deletion** | Correlations with MCAR gaps | Inconsistent n across results |
    | **Mean/median imputation** | MCAR, small share, non-key fields | Shrinks variance, distorts relationships |
    | **Missing indicator / "not stated" category** | MNAR or informative missingness | Must be documented; works well in scorecards (own WoE bin) |
    | **Model-based (KNN, regression, MICE)** | MAR with good predictors | Complex; still biased under MNAR |
    | **Sensitivity analysis** | Always for MNAR | Shows how much the conclusion depends on assumptions |

    ### 2.4 Silent row loss

    Many tools drop incomplete rows without telling you. A model using `income_annual` and `utilisation` keeps only
    **{{ a.d1_listwise_rows | n }}** of {{ a.fi_rows | n }} accounts ({{ a.d1_listwise_drop_pct }}% dropped): utilisation is
    *structurally* missing for every personal loan, so all loans vanish — plus the risky missing-income customers.

=== "Leader"

    !!! abstract "Refresh"
        MCAR (no pattern) → deletion is safe. MAR (explained by observed fields) → condition on them or impute from them. MNAR (depends
        on the unseen value) → keep a missing category and run sensitivity analysis. Tests rule MCAR out, never in.

    **Judgement points**

    - **Missingness is often information.** Default is {{ a.d1_def_inc_missing_pct }}% when income is missing vs
      {{ a.d1_def_inc_known_pct }}% when present. Deleting those rows removes your riskiest customers from the model.
    - **Deletion biases risk estimates.** Card default drops from {{ a.d1_cards_default_pct }}% to
      {{ a.d1_cards_listwise_default_pct }}% after listwise deletion — a provisioning model would under-reserve.
    - **"Structurally missing" ≠ missing.** Utilisation does not exist for loans; treat it as "not applicable", model products separately.
    - **Ask for the missingness table first.** Rows missing by field, rate by key segments, outcome when missing vs present.

    !!! tip "Coaching card"
        When a junior says "I dropped the nulls", ask three questions: *how many rows, which segments lost the most, and does the outcome
        differ for the dropped rows?* Most silent biases surface on the third question.

## 3. Assumptions and fallbacks

| Situation | Do | Fallback |
| --- | --- | --- |
| < 5% missing, consistent with MCAR at the right unit | Simple imputation or deletion, documented | — |
| Missingness explained by observed fields (MAR) | Stratify / impute using those fields | Multiple imputation |
| Outcome differs when missing (possible MNAR) | Missing indicator or "not stated" category | Sensitivity analysis (best/worst case) |
| Field not applicable to a segment | Model segments separately | Encode "not applicable" explicitly |

## 6. Scenario matrix

=== "Basic → Advanced"

    | Pattern | Classification | Treatment |
    | --- | --- | --- |
    | Rate flat across segments, outcome similar | Consistent with MCAR | Delete or impute simply |
    | Rate differs by an observed field | MAR | Condition on / impute from that field |
    | Tests pass but outcome differs | Possibly MNAR | Missing category + sensitivity |
    | Field missing for a whole segment | Not applicable | Separate models |

=== "Leader"

    | Pattern | Risk | Action — why / when / when not | Norm |
    | --- | --- | --- | --- |
    | Risky customers more often missing income | Model under-predicts risk | **Keep missing as its own bin**; never impute with the mean | Scorecards treat missing as an attribute |
    | Large row loss in a model sample | Population mismatch | **Reject** until row accounting and segment impact shown | Explain any drop > 5% |
    | Survey field missing for top customers | Profiles biased | Report coverage with every profile; do not extrapolate | State coverage on every chart |
    | Imputation changes a KPI materially | Conclusion depends on assumption | Show both versions; decide which is policy | Sensitivity analysis for MNAR |
