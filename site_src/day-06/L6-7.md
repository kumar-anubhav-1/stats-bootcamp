## 2. Concept

=== "Basic → Advanced"

    ### 2.1 Global: permutation importance

    Shuffle one feature in the test set and measure how much AUC drops. Gradient-boosting default model:

    | Feature | AUC drop when shuffled |
    | --- | --- |
    {% for k, v in a.d6_perm_imp.items() %}| {{ k }} | {{ v }} |
    {% endfor %}

    Bureau score dominates; channel and utilisation follow. **Impurity-based importance** (the default in many tree libraries) favours
    high-cardinality and continuous features and is computed on training data — prefer permutation importance on held-out data.
    Correlated features share importance (income vs limit, L5.2): shuffling one leaves the other to carry the signal.

    ### 2.2 Shape: partial dependence

    Average predicted PD as utilisation varies (others held at observed values):

    | Utilisation | {% for p in a.d6_pdp_util %}{{ p[0] }} | {% endfor %}
    | --- | {% for p in a.d6_pdp_util %}--- | {% endfor %}
    | Avg predicted PD | {% for p in a.d6_pdp_util %}{{ p[1] }}% | {% endfor %}

    Flat at low utilisation, rising steeply past ~0.7 — the F04 shape the model learned. ICE plots show the same curve per customer
    to reveal interactions (some customers' curves rise much faster).

    ### 2.3 Local: why this applicant?

    For a logistic model, each feature's contribution to the log-odds is β × (x − average x) on the standardised scale — the basis of
    scorecard **reason codes**. The highest-risk test applicant (PD {{ a.d6_case_pd }}%): top three adverse factors
    **{{ a.d6_case_reasons | join(", ") }}** (values: {{ a.d6_case_values | kv }}).

    **SHAP** generalises this to any model: it splits each prediction into feature contributions that add up to the difference from
    the average prediction (Shapley values from game theory). TreeSHAP is fast for tree ensembles. Use SHAP for local explanations of
    GBMs (install the `shap` package); global SHAP summaries also show direction and spread.

    ### 2.4 What explanations do not do

    They explain **the model**, not the world. A feature with high importance is predictive, not necessarily causal (L4.4). Explanations
    of a leaky or biased model faithfully explain a bad model.

=== "Leader"

    !!! abstract "Refresh"
        Permutation importance and PDPs explain models globally; reason codes and SHAP explain individual decisions. Explanations
        describe the model, not causality.

    **Judgement points**

    - **Adverse-action notices** (ECOA/Reg B, GDPR Art. 22 contexts) need specific, stable, accurate reasons — logistic scorecards
      give them natively; GBMs need SHAP with governance on stability.
    - **Use explanations to catch problems:** a post-outcome field at the top (L6.4), a proxy for a protected attribute (L9.5), or an
      implausible direction.
    - **Don't let importance charts become strategy.** "Bureau score matters most" is not a lever.

    !!! tip "Coaching card"
        Ask: *"Show me global importance, one PDP for the top driver, and the reasons for three individual declines. Would the reasons
        survive a complaint?"*

## 5. Output anatomy — explanation artefacts

| Artefact | Question it answers |
| --- | --- |
| permutation importance | which features does the model rely on? |
| PDP / ICE | how does the prediction change with one feature? |
| reason codes / SHAP | why this prediction for this customer? |
| stability check | do reasons change across refits? |
