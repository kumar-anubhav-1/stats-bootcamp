## 2. Concept

=== "Basic → Advanced"

    ### 2.1 Methods

    | Method | Idea | Strength | Watch |
    | --- | --- | --- | --- |
    | Robust z (median/MAD) | distance from the median in robust SD units | simple, not masked by the outliers | MAD = 0 when most values equal |
    | Control chart / CUSUM | deviation from a stable process over time | monitoring | needs a stable baseline |
    | Residual-based | unusual given a model (expected returns for this basket mix) | context-aware | model quality |
    | Isolation Forest | anomalies are easy to isolate with random splits | multivariate, no distribution | contamination choice, explainability |
    | LOF | low local density vs neighbours | local outliers | scaling, parameter k |

    ### 2.2 Returns abuse (R17)

    {{ a.d8_r17_n_cust | n }} customers with ≥ 5 lines. Planted abusers return **{{ a.d8_r17_rate_true }}%** of purchases vs
    {{ a.d8_r17_rate_other }}% for others, concentrated in {{ a.d8_r17_stores }} stores.

    **Degenerate scale:** {{ a.d8_zero_return_share }}% of customers never return anything, so the median return rate is 0 and the MAD is
    0 — every returner gets an infinite robust z. Fall back to the mean absolute deviation (the recipe does this automatically).

    | Method (top {{ a.d8_r17_n_true }} flagged) | Precision vs planted abusers |
    | --- | --- |
    | Robust z on return rate | **{{ a.d8_prec_robustz }}%** |
    | Isolation Forest (rate, returns, lines, stores) | {{ a.d8_prec_iso }}% |
    | Most returns (count) | {{ a.d8_prec_returns_count }}% |
    | Rule: return rate > 20% | recall {{ a.d8_rule20_recall }}%, precision {{ a.d8_rule20_precision }}% |

    Rates beat counts (counts favour big shoppers); the multivariate forest is not automatically better than a well-chosen metric.

    ### 2.3 Contamination = alert budget

    At 1%, 2% and 5% contamination the scan flags {{ a.d8_flag_at_1pct }}, {{ a.d8_flag_at_2pct }} and {{ a.d8_flag_at_5pct }}
    customers. Choose by how many cases loss prevention can review, then check how stable the list is across methods.

=== "Leader"

    !!! abstract "Refresh"
        Anomaly detection ranks entities for review; the review capacity sets the cut-off. Simple robust metrics often beat complex
        models; flagged lists are leads, not accusations.

    **Judgement points**

    - **Due process:** returns-abuse flags lead to review and, if confirmed, policy action — never automatic bans on a score.
    - **Precision at the review budget** is the KPI; track confirmation rates of reviews to tune.
    - **Look for clusters** — the abusers sit in a few stores (collusion or local policy gaps).

    !!! tip "Coaching card"
        Ask: *"How many can we review, what share of those turn out real, and what happens to a flagged customer?"*
