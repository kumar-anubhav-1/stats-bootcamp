## 2. Concept

=== "Basic → Advanced"

    ### 2.1 Methods

    | Method | Finds | Needs | Watch |
    | --- | --- | --- | --- |
    | K-Means | round, similar-size groups | k, scaled features | sensitive to scale and outliers |
    | Hierarchical | a tree of merges (dendrogram) | linkage choice | slow for large n |
    | DBSCAN | dense regions; labels noise | density parameters | struggles with varying density |
    | Gaussian mixture | soft (probabilistic) clusters, elliptical shapes | k, covariance type | can overfit |

    ### 2.2 Customer segments ({{ a.d8_n_cust_clust | n }} customers with ≥ 2 baskets, {{ a.d8_n_feat_clust }} features)

    Features: baskets, revenue (log), average basket, promo share, price ratio, list price, category shares — **all scaled**.

    | k | {% for k in a.d8_sil %}{{ k }} | {% endfor %}
    | --- | {% for k in a.d8_sil %}--- | {% endfor %}
    | Silhouette | {% for v in a.d8_sil.values() %}{{ v }} | {% endfor %}

    Silhouette (−1 to 1; > 0.5 strong, < 0.25 weak) peaks at k = {{ a.d8_sil_best_k }} but is **weak everywhere** — customers form
    a continuum, not tidy islands. The planted truth has 5 segments; K-Means with k = 5 recovers them only partly (adjusted Rand index
    **{{ a.d8_ari }}**, R23).

    | Cluster (k = 5) | Customers | Median baskets | Median revenue | Promo share | Top category |
    | --- | --- | --- | --- | --- | --- |
    {% for k, p in a.d8_profiles.items() %}| {{ k }} | {{ p.n }} | {{ p.baskets }} | {{ p.revenue | n }} | {{ p.promo_pct }}% | {{ p.top }} |
    {% endfor %}

    Even with weak overall structure, one segment is unmistakable: **promo hunters** (promo share ~64%, Snacks-heavy) — distinct,
    sizeable and actionable (targeted offers, margin control).

    **Scaling matters:** clustering the same features unscaled agrees with the scaled solution only ARI {{ a.d8_ari_unscaled }} —
    revenue's large numbers dominate.

    {{ chart("kmeans3d", "Rotate and drag k: clusters overlap (low silhouette) — real customers rarely form tidy blobs.") }}

    ### 2.3 PCA

    Principal components are uncorrelated combinations of features ordered by variance (L2.7). The first two explain
    **{{ a.d8_pca_2 }}%**; {{ a.d8_pca_n_for_80 }} are needed for 80% — information is spread out. Use PCA for visualisation and
    de-noising; t-SNE/UMAP make pretty maps but distort distances — don't cluster on them.

    {{ chart("pca3d", "Rotate: 14 features squeezed into 3 components; colour = promo share.") }}

=== "Leader"

    !!! abstract "Refresh"
        Clustering always returns clusters. The questions are whether they are distinct, stable and useful. Scale features; choose k
        with silhouette plus business sense; profile and name segments by what you would do differently.

    **Judgement points**

    - **Actionability beats silhouette.** A weak-structure solution with one clearly actionable segment (promo hunters) is worth more
      than a "perfect" k nobody can use.
    - **Stability check:** re-run with different seeds and periods; segments that reshuffle are not a basis for strategy.
    - **Personas need numbers** — size, value, behaviour — not just names.

    !!! tip "Coaching card"
        Ask: *"How big is each segment, how would we treat it differently, and does it survive a re-run next quarter?"*

## 6. Scenario matrix

=== "Basic → Advanced"

    | Data | Method |

    | need soft membership | Gaussian mixture |
    | noise/outliers, arbitrary shapes | DBSCAN |

    | many correlated features | PCA first |
